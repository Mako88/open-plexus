Can a predictive objective bootstrap on MQAR? -- and is the task learnable at all?
==================================================================================

Script: experiments/g1_02_train.py
Status: RUN, 5 seeds. ALL FOUR PREDICTIONS HELD. G0 step 3 is closed, the
        predictive objective bootstraps perfectly, and note 008's recommended
        task change is MOOT.


IN PLAIN TERMS
--------------
Two questions, one experiment.

First: is our memory test learnable at all? Everything so far shows it is
answerable (a cheat with the answers gets 100%) and reachable (a hand-written
lookup gets 100%), but nothing has ever LEARNED it. If nothing can, then all the
room we found is unreachable and every future failure would be uninterpretable.

Second, and the reason John asked for this: our learning method works by
predicting the next thing in the sequence. Most of the sequence is meaningless
padding. Does the method get distracted by the padding, or does it find the
part that matters?

We can test both at once by training the same model two ways: once told exactly
which answers to get right, and once left to predict everything for itself. The
first is the ceiling. The second is the real question.


QUESTION
--------
Train a single-head shifted-value attention model on autoregressive MQAR.

  objective=answers   loss on query positions only -- the model is told which
                      predictions matter. This is SUPERVISED and is the ceiling.
  objective=all       loss on every position -- pure next-token prediction, with
                      no indication of which positions matter. This is the
                      self-supervised objective docs/notes/002 recommends.

  filler=random       unpredictable padding
  filler=structured   a predictable cycle

Scored throughout on held-out sequences, at query positions, against
MqarConfig.trivial_floor (0.344 at the reference) -- NOT against the base rate,
which g0-01 established is the flattering wrong bar.


PREDICTIONS -- written before the run
--------------------------------------
1. objective=answers, filler=random: HIGH, above 0.90.
   The architecture can express the solution by construction (shifted values),
   and the supervision is direct. If this fails, the model or the training loop
   is broken and nothing else in the table means anything -- it is the
   connection control for the whole experiment.

   **If it succeeds it also closes G0 step 3**: a model trained from scratch on
   our own generator reaching near ceiling is exactly the evidence that the task
   is LEARNABLE, which the oracle and the hand-written lookup could not supply.

2. objective=all, filler=random: HIGH, and close to (1). Perhaps slower.
   This is docs/notes/008 §4's argument put to the test. That note claims
   irreducible loss contributes no gradient, so with unpredictable padding the
   only place loss can fall is the answer positions, and the objective should
   concentrate there without being told to.

3. objective=all, filler=structured: MUCH WORSE than (2). Same note, other half:
   predictable padding offers a large, easy loss reduction at ~83% of positions,
   so gradient should flow there instead. Guess: at or near the trivial floor.

   The GAP BETWEEN (2) AND (3) is the actual measurement. It is the first direct
   test of docs/notes/008 §4, which was pure argument.

4. Filler-position accuracy stays near chance under random filler and gets high
   under structured filler. A cheap consistency check against g1-01, which
   measured 0.029 and 0.824 for a frozen substrate.

Most likely to be wrong: (2). The honest uncertainty is whether "no reducible
loss at padding positions" is enough, or whether a predictive objective needs
some positive gradient early on to get started at all -- 4% of positions
carrying all the signal may simply be too sparse to escape initialisation, which
would be a bootstrapping failure of a different kind than note 008 described.


WHAT WOULD REFUTE WHAT
-----------------------
- (1) fails                  -> model or training loop broken; discard the table
- (2) ~= (1)                 -> THE MISMATCH IS NOT REAL. A predictive objective
                                bootstraps on MQAR with random filler, note 008's
                                three directions are moot, and the project
                                continues on the task it already has
- (2) at the trivial floor   -> the predictive objective cannot bootstrap here
                                even with padding that offers no distraction.
                                Note 008's recommendation stands and the task
                                needs changing
- (2) ~= (3)                 -> note 008 §4 is WRONG. Filler predictability makes
                                no difference, so "reducible loss is what drives
                                learning" fails to predict behaviour, and the
                                one-word fix that note recommended is worthless
- (3) >= (2)                 -> note 008 §4 has the sign wrong AGAIN, in the
                                other direction. Would be the second sign
                                inversion on the same question and cause for
                                distrusting the whole line of argument


A NOTE ON WHAT (1) IS AND IS NOT
---------------------------------
objective=answers is SUPERVISED: the model is told which positions matter. That
is a C1 violation and could never run distributed. It is included purely as a
ceiling and a connection control, exactly as the strong non-local reference in
G0 step 3 always was. Nothing about using it implies anything about the
architecture being proposed.


RESULT
------
4000 steps, 600 train / 200 held out, d_model=64, 5 seeds per condition.
Trivial floor 0.344. Base rate 0.125.

objective  filler        query acc   floor  filler acc   across seeds
---------------------------------------------------------------------
answers    random            1.000   0.344       0.000   all equal
all        random            1.000   0.344       0.032   all equal
all        structured        0.009   0.344       0.775   0.005-0.013

"all equal" means the five seeds agreed to within 5e-4.


1. HELD. Supervised ceiling 1.000, identical on 5/5 seeds.

   **G0 STEP 3 IS CLOSED.** A model trained from scratch on our own generator
   reaches ceiling. The task is not merely answerable (the oracle) and reachable
   (the hand-written lookup) but LEARNABLE. The 0.82 of headroom g0-02 found is
   available rather than theoretical, and every future null on this benchmark is
   now interpretable.

2. HELD, and completely. Pure next-token prediction over every position, with no
   indication of which positions matter, reaches 1.000 -- IDENTICAL to being
   told the answers. 5/5 seeds.

   **The mismatch docs/notes/008 was written about is not real.** With
   unpredictable padding the self-supervised objective finds the task on its own.
   Its three directions -- switch tasks, split roles, reconsider the objective --
   are all moot, and the project continues on the benchmark it already has.

3. HELD, and dramatically. Structured filler: 0.009. Not merely worse -- an
   order of magnitude BELOW the 0.125 base rate, because the model learns to
   emit filler-like tokens everywhere.

   The gap between (2) and (3) is 1.000 against 0.009 from a one-word change.
   **docs/notes/008 §4 is confirmed on the strongest possible evidence.**

4. HELD. Filler accuracy 0.032 under random, 0.775 under structured, against
   g1-01's frozen-substrate measurements of 0.029 and 0.824. Consistent.


THE NEAR MISS
-------------
docs/notes/002 §7 originally recommended STRUCTURED filler, and that
recommendation stood for several days as the resolution to a tension the note
had correctly identified.

Had it been acted on, this experiment would have returned 0.009.

The reading would have been: "the self-supervised predictive objective does not
learn the task; the supervised ceiling reaches 1.000, so the model and the task
are fine; therefore the objective is the problem." That conclusion is wrong, it
is exactly what the numbers would have supported, and it would have discredited
the central hypothesis of the project on the strength of a padding setting.

The error was caught by note 008 §4 reasoning about WHERE REDUCIBLE LOSS LIVES,
using numbers that had been sitting in g1-01 for two sweeps. Nothing failed. No
test could have caught it. The one-word fix is the difference between the
project's central bet looking confirmed and looking dead.


THE LOSS CURVE IS A TRAP
-------------------------
Worth recording separately, because it is the most transferable thing here.

  all / random      loss 3.654 -> 3.320   query accuracy 1.000
  all / structured  loss 3.052 -> 1.824   query accuracy 0.009

**The configuration that solves the task has an almost flat loss curve. The
configuration that fails catastrophically has a steeply falling one.**

Anyone monitoring training loss -- the single most common thing to monitor --
would have concluded the second run was going well and the first was stuck. Both
readings are exactly backwards.

The reason is note 008 §4 restated: with random filler ~83% of the loss is
IRREDUCIBLE, so the total barely moves however well the model does on the part
that matters. With structured filler that same 83% is reducible and easy, so the
total plummets while the task is ignored.

**Loss is a sum over positions and the task lives in 4% of them. A metric that
averages over positions cannot see the task.** Score what you care about, at the
positions you care about -- rule 2, with a number attached.


WHAT THIS DOES NOT SETTLE
--------------------------
- **This model is not the proposal.** Attention is a C1 violation: every position
  attends to every earlier position, which is exactly the all-to-all pattern this
  project exists to avoid. It was built to answer whether the OBJECTIVE can
  bootstrap, and it has. Whether a LOCAL rule can do the same is G1 proper and is
  entirely open.
- **The architecture was handed the induction shape.** Values are shifted by one
  by construction, so the model did not have to discover that structure. Whether
  it bootstraps without that help is untested and is the obvious next question.
- **One task, one configuration.** n_pairs=4, seq_len=64. The difficulty dials
  exist and have not been swept against a trained model.
