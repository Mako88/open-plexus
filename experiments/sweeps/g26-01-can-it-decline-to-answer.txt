Can it decline to answer?
==========================

Script: experiments/g26_01_abstention.py  (to be written)
Status: NOT RUN. Predictions registered and committed before the script exists.

ANSWER: pending.


IN PLAIN TERMS
---------------
Ask the system something it was never told and it will answer anyway. It has no
way to say "I do not know" -- nothing decides to stay quiet, and no test would
notice if something did.

There is one piece already in place: the system can check whether anything was
ever written at an address. That is not a guess about confidence, it is a fact
about storage, and at an address nobody wrote to it reads **exactly zero**.

So the question is whether that fact is enough to decline honestly. Ask about a
person's job when only family relationships were ever stored, and the address for
"this person's job" was never written. If the system notices that, it can say so.

**Why it matters:** a system that confidently answers what it was never told is
worse than one that answers less. This is the first test here that scores staying
quiet.


WHY THIS EXISTS
----------------
`docs/options/declining-to-answer.md`:

    No mechanism decides to abstain and no instrument would notice if one did,
    so any claim about honesty here is untested.

The pieces exist and have never been connected:

    the gate        reads EXACTLY 0.0 at an address nobody wrote. `148` measured
                    it at 1.0000 / 0.0000 on transfer against direct, every seed,
                    and the threshold is structural rather than tuned
    render.speak    declines on an empty set rather than rendering a hole
    nothing         decides to abstain, and no task scores it

**The limit is already stated in the record and this sweep does not test past
it:** the gate is *"unable to say 'I do not know' about a question whose
addresses are all occupied"*. A written-but-wrong answer is out of scope. What is
in scope is the common real case -- a known entity, a relation never stored for
it.


THE MEASUREMENT
---------------
Two question classes over the same store:

    ANSWERABLE     `(entity, relation)` was written. Answering is correct;
                   abstaining is a FALSE ABSTENTION and costs a real answer
    UNANSWERABLE   `(entity, relation)` was never written, though the entity is
                   known and the relation is known. Abstaining is correct;
                   answering is a CONFIDENT FABRICATION

Scored as a pair, never averaged. **A model that abstains always scores 1.000 on
unanswerable and 0.000 on answerable**, which is the same trap `165` names for
recall on set answers -- and it degenerates exactly, so both numbers are always
reported.


PREDICTIONS
-----------
  P1  THE GATE. On ANSWERABLE questions the false-abstention rate is below 0.05.

      If the model abstains on questions it can answer, abstention is not a
      capability, it is a fault, and nothing below is worth reading.

  P2  THE TEST. On UNANSWERABLE questions the abstention rate is above 0.90.

      Refuted below that, which would mean the occupancy signal does not survive
      contact with a question -- and since it is exact at the address, the
      failure would be in how the question reaches the address rather than in
      the gate.

  P3  Abstention costs NOTHING on the answerable half: accuracy with the gate on
      is within 0.01 of accuracy with it off.

      The gate only fires where nothing was written, so it should never intercept
      an answerable question. Refuted means it is intercepting them, which is P1
      from the other side and a stronger version of it.

  P4  THE ONE I EXPECT TO BE WRONG. Abstention is EXACT -- 0.000 false and 1.000
      correct.

      `148` measured the gate itself as exact, so the temptation is to expect
      that here. **I expect not**, because `note 071` measured `AddressSketch` at
      its default 16 bits with a false-hit rate of **0.0044 to 0.0100**: a
      fraction of unanswerable questions will find a spurious occupancy and
      answer instead of declining. If P4 fails in that direction and at about
      that rate, the abstention ceiling is the sketch's false-hit rate and not
      the gate, which is a different thing to fix and points at bit width.


WHAT WOULD MAKE THIS NOT COUNT
--------------------------------
**An unanswerable question that is unanswerable for the wrong reason.** If the
entity or the relation is itself unknown, the question fails at the vocabulary
rather than at the address, which is a much easier problem. Both must be known
and only the PAIR unwritten, and the generator asserts that rather than assuming
it.

**Averaging the two classes.** One number hides a model that abstains always.
Both are always printed side by side.

**Base rates.** The proportion of unanswerable questions is a free parameter and
a model could look good by matching it. It is reported, and the two rates are
independent of it by construction since they are computed within class.


COST
----
One store, two question sets, no training beyond the existing kinship setup.
Minutes, local, no dispatch.


MEASURED ON
-----------
`openplexus/tasks/families.py` or `kinship.py`, whichever supplies a known entity
with an unwritten relation without modification. The instrument choice is recorded
in the result rather than assumed here, and if NEITHER supplies it that is itself
the finding -- no existing task can pose an unanswerable question.
