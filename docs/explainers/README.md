# Explainers

Plain-language explanations of everything in this project, in reading order.

**These are not summaries of the technical docs — they are the same ideas
written for someone who does not work in this field.** No jargon without a
definition. No numbers that need another document to understand. Short enough to
read on a phone.

They exist because of a specific risk: **a project its owner cannot follow is a
project where nobody can tell it that it is wrong.** The whole method here
depends on being able to challenge a claim, and you cannot challenge what you
cannot read. If any explainer stops making sense, that is a defect in the
explainer, and saying so is the most useful thing you can do.
