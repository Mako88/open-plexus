G0 step 2 -- what does a frozen random substrate score?
========================================================

Script: experiments/g0_02_reservoir.py
Status: RUN. Prediction 1 REFUTED in the direction flagged as possible -- the
        reservoir scores BELOW the trivial floor and barely above chance.
        Prediction 4 held emphatically. 2 held weakly, 3 refuted, 5 roughly held.


IN PLAIN TERMS
--------------
A random, untrained network is surprisingly capable. Attach a simple trained
reader to its output and it can do a lot -- which is exactly the trap that cost
the previous project a year, because if the untrained version already scores
well there is no room left to show that learning helped.

So before building anything that learns, we measure what the untrained version
gets. We want this number to be LOW. A low score here is good news: it means
there is room for a learning rule to show up in.

A high score would be bad news, and we would want to know now rather than after
six months of building against a benchmark that cannot separate anything.


QUESTION
--------
Does a frozen random reservoir with a trained linear readout leave headroom on
MQAR, measured against the trivial floor from g0-01 below and the oracle's 1.000
above?

Readout is fitted on training sequences and scored on held-out ones. Fitting and
scoring on the same data would let an underdetermined fit interpolate and report
a strong-looking artefact.


PREDICTIONS -- written before the run
--------------------------------------
1. The reservoir scores ABOVE the trivial floor but WELL BELOW 1.000. Somewhere
   in 0.40-0.70 at the reference, against a floor of 0.344.

2. Score rises with n_units. Memory capacity is bounded by the number of state
   variables (docs/notes/006 §2), so a wider substrate should hold more pairs.
   16 units < 64 units < 128 units.

3. Score falls as n_pairs rises. Fixed capacity, more to remember. The fall
   should be steeper than the floor's own fall, so HEADROOM WIDENS with n_pairs.

4. Headroom at the reference exceeds 0.30. This is the number G0 exists to
   produce, and anything under ~0.2 would make the benchmark as unusable as the
   predecessor's.

5. Filler mode barely matters. A frozen substrate cannot exploit the
   predictability of structured filler -- exploiting it would require learning,
   and nothing here learns.

The prediction most likely to be wrong is (1), and it could fail in either
direction, which is why it is worth running:

  - It could score AT or BELOW the floor, meaning a linear readout on reservoir
    state is worse than "emit any value you have seen". That would be a fine
    outcome for G0 (maximum headroom) and a bad one for the reservoir's dignity.
  - It could score much higher than 0.70, which would be the predecessor's
    failure repeating and would force a harder configuration.


WHAT WOULD REFUTE WHAT
-----------------------
- reservoir >= ~0.85            -> not enough headroom; the benchmark cannot
                                   separate a learning rule from a random one
- reservoir <= floor            -> the reservoir adds nothing over a heuristic;
                                   headroom is maximal but the floor, not the
                                   reservoir, is the real control
- no rise with n_units          -> capacity is not the binding constraint here,
                                   or the readout is not connected to the state
- headroom narrows with n_pairs -> n_pairs is the wrong difficulty dial, which
                                   would contradict both docs/notes/006 and
                                   g0-01


WHAT THIS DOES *NOT* ESTABLISH
-------------------------------
G0 step 3 -- the strong non-local reference -- is NOT done here, and the oracle
is not a substitute for it. The oracle is *given* the answers, so it shows the
task is ANSWERABLE. It does not show the task is LEARNABLE.

Those are different claims and conflating them would be a real error: a task can
be answerable-in-principle and beyond what any trainable model achieves, and a
benchmark like that would make every future null result uninterpretable.

The published evidence that a 2-layer transformer solves this task perfectly
(docs/notes/006 §4) is real but is about the source's variant, not ours. Until
something is trained on OUR generator and scores near ceiling, G0 is incomplete
and should be described that way.


RESULT
------
240 training / 160 held-out sequences per condition. Base rate is 0.125
throughout (n_values=8).

condition          floor   frozen  CONTROL  headroom
----------------------------------------------------
reference          0.344    0.180    1.000     0.820
n_units=16         0.344    0.155    0.777     0.845
n_units=128        0.344    0.188    1.000     0.812
n_pairs=2          0.562    0.144    1.000     0.856
n_pairs=8          0.234    0.143    1.000     0.857
filler=random      0.344    0.138    0.992     0.863

CONTROL is the same pipeline decoding the token currently being presented --
information the state provably holds, since that token is the input driving it.


THE CONTROL IS WHY THIS RESULT IS BELIEVABLE
---------------------------------------------
The control was added after the first run produced 0.180 and before that number
was written down anywhere as a finding.

A frozen reservoir failing associative recall is precisely what docs/notes/006
predicted. That is the problem: a broken pipeline produces the same output as a
confirmed prediction, and a confirmed prediction is exactly the condition under
which nobody looks harder.

CONTROL = 1.000 at the reference. The readout decodes the current token
perfectly from the same states, fitted the same way, scored on the same held-out
split. The substrate-to-readout path is not merely working, it is flawless. So
0.180 is a property of the substrate.

(At n_units=16 the control is 0.777, not 1.000 -- 16 dimensions cannot linearly
separate 41 token classes. That condition is capacity-limited in the pipeline as
well as the task, and its recall number should not be compared with the others.)


WHAT WAS FOUND
--------------
The frozen reservoir is AT CHANCE on MQAR. 0.180 against a base rate of 0.125,
and below the trivial floor of 0.344 in every non-degenerate condition. It is
not doing the task poorly. It is not doing the task.

1. REFUTED. Predicted 0.40-0.70, above the floor. Measured 0.180, below it. The
   direction was flagged in advance as possible and it is the one that happened.

2. Weakly held. 0.155 (16 units) -> 0.180 (64) -> 0.188 (128). It rises, but
   DOUBLING the substrate buys 0.008. Capacity is not the binding constraint at
   these sizes; content-addressed retrieval is, exactly as docs/notes/006 §5
   describes -- the requirement is input-dependent mixing, which no amount of
   width supplies.

3. REFUTED. 0.144 (2 pairs) -> 0.180 (4) -> 0.143 (8), non-monotonic. With
   everything within 0.06 of chance these are noise, not a trend. The prediction
   assumed the reservoir was doing something that degraded; it never was.

4. HELD, emphatically. Headroom 0.82 at the reference, against the >0.30 the
   prediction asked for. Compare the predecessor: a 0.802 baseline with ~0.19 of
   total headroom, of which non-learning mechanisms took 40%. This benchmark has
   more than four times that room and none of it is already spent.

5. Roughly held. 0.180 structured vs 0.138 random. Both near chance.


TWO CONSEQUENCES
----------------
A. THE RESERVOIR IS NOT THE CONTROL ANY MORE. It scores BELOW the one-line
   heuristic. The bar a learning rule must clear is max(floor, frozen) = the
   FLOOR, 0.344 at the reference. Reporting a future model against "the frozen
   reservoir's 0.180" would credit as progress something a heuristic already
   beats. G0's protocol in docs/notes/001 §6 lists the frozen substrate as the
   floor that matters; that ordering is wrong here and the note needs it.

B. docs/notes/006 §9's open item is closed. That note recorded that a random
   frozen reservoir was NOT among the architectures the source tested, so its
   position on this benchmark was inferred by analogy from gated convolutions
   and state-space models. It is now measured on our own generator, and the
   inference was correct.


STILL NOT DONE -- G0 IS INCOMPLETE
-----------------------------------
G0 step 3, the strong non-local reference, has not been run. The oracle scores
1.000 but is *given* the answers: it shows the task is ANSWERABLE, not that it
is LEARNABLE.

This matters more now, not less. A benchmark where the untrained control sits at
chance is only useful if something trainable reaches high. If nothing does, then
0.82 of headroom is unreachable rather than available, and every future null
would be uninterpretable -- indistinguishable from the task simply being too
hard for anything.

Published evidence says a 2-layer transformer solves this task perfectly, but on
the source's variant, not ours. Until something is TRAINED on this generator and
scores near ceiling, G0 is incomplete and must be described that way.
