G1 -- what does a LOCAL rule need, against what backprop needs?
================================================================

Script: experiments/g1_05_local.py
Status: RUN on GitHub Actions, 48/48 cells. Predictions 1 and 2 HELD -- the
        local rule works, at roughly 4-6x the width. And an unpredicted finding
        that matters more than either: THIS RULE IS NOT BIMODAL.


IN PLAIN TERMS
--------------
This is the actual bet the whole project rests on.

Everything that has solved our memory test so far did it in a way that could
never run on strangers' computers: every part of the model looks at every other
part, and learning works by sending information backwards through the whole
thing. That is what needs a data centre.

So we built the alternative -- a system where every update a connection makes
depends only on what its own two ends are doing. Nothing looks at everything.
Nothing travels backwards.

Does it work? And if it works, how much bigger does it have to be?

That second question is the useful one. The unrestricted model needs somewhere
between 8 and 16 numbers to think with. If ours needs 64, then "four to eight
times bigger" is the price of running on ordinary machines -- a real number we can
argue about. If it never works at any size, that is a different and much worse
answer.


QUESTION
--------
g1-04 established that difficulty for a competent model lives in MODEL WIDTH, not
in the task parameters, and gave the attention model's threshold: 0/8 solved at
d_model 4 and 8, 8/8 at 16 and above.

So: sweep d_model for the local rule on the same task, at the same success
criterion, and compare where each crosses.

THE LOCAL RULE
  store      M += v(x_t) (x) k(x_{t-1})      Hebbian outer product. Entry [i,j]
                                             changes by the product of a signal
                                             at its output side and one at its
                                             input side. Nothing else consulted.
  retrieve   r = M k(x_t)                    matrix-vector; each output sums over
                                             its own incoming connections
  predict    y = Wo r
  learn      Wo += lr (target - y) (x) r      delta rule; the error is the unit's
                                             own, against its own next input

No softmax over positions. No backward pass. Wk and Wv are frozen random -- only
Wo learns, which is the strictest version of the question.

Reported as SOLVED / STUCK counts (g1-03: outcomes are bimodal, so a mean
describes a mixture of two populations and no actual run).


PREDICTIONS -- written before the run
--------------------------------------
1. It works at SOME width. The mechanism is a fast-weight associative memory,
   which is what content-addressed retrieval looks like when built out of local
   operations, and g0-03 showed one hand-written lookup closes the entire gap.
   This is that lookup, learned Hebbianly instead of written down.

2. It needs MORE width than attention -- this is the central prediction and the
   number the experiment exists to produce. Guess: crosses somewhere between 64
   and 256, so a 4x-16x penalty.

   The reason to expect a penalty rather than parity: this computation is what a
   LINEAR-attention layer does, and docs/notes/006 records that linear attention
   fails MQAR unless its state is large while softmax attention does not. A
   softmax picks one match; an outer-product store superposes every binding it
   has seen and the retrieval returns the right one plus interference from all
   the others. Width is what buys the room for those to stay separable.

3. The penalty grows with n_pairs. More bindings superposed in one matrix means
   more interference, and unlike attention -- which g1-04 measured as completely
   flat in n_pairs -- this rule should care. If so, **n_pairs becomes a real
   difficulty dial for the first time**, for exactly the reason it was not one
   before.

4. decay < 1.0 does not help at the reference size. It bounds interference by
   forgetting, but MQAR needs every binding retained until its query arrives, so
   forgetting should cost more than the interference it prevents.

Most likely to be wrong: (2)'s magnitude. The honest range is wide. Two outcomes
would each be more interesting than the middle:
   (a) parity with attention, meaning locality is free on this task, which would
       be a surprisingly good result and would need checking hard for a leak;
   (b) never crosses at any width tested, meaning superposition interference is
       not something width fixes, and the rule needs a mechanism for keeping
       bindings apart rather than more room.


WHAT WOULD REFUTE WHAT
-----------------------
- crosses at 8-16            -> parity. Locality free here. Check for a leak
                                before believing it
- crosses at 64-256          -> as predicted; the ratio is the price of locality
- never crosses              -> width is the wrong remedy; interference needs
                                addressing directly. NOT a refutation of the
                                project, but a much harder road
- n_pairs flat for this rule -> superposition interference is not the mechanism
                                and prediction 2's reasoning is wrong even if its
                                number is right


A NOTE ON WHAT THIS IS NOT
---------------------------
This is a locality-RESPECTING computation running in one process. It is not
distributed and nothing here tests delay or churn -- those are G2 and G3. What is
being tested is whether the C1 constraint is affordable at all, which has to come
first: a rule that cannot learn in one process will not learn spread over
thousands.

PREDICTION 1 HELD -- THE LOCAL RULE WORKS
------------------------------------------
8/8 at d_model=64 and above, with worst-case 0.981.

A rule in which every update is a product of two signals present at the synapse,
with no softmax over positions and no backward pass anywhere in the code, solves
a task that a frozen substrate scores 0.180 on and a one-line heuristic scores
0.344 on. **C1 is affordable on this task.**

That is the first evidence in this project that the central constraint is not
fatal, and it is what G1 existed to find out.


PREDICTION 2 HELD, AT THE OPTIMISTIC END
-----------------------------------------
Predicted a crossing between 64 and 256, a 4x-16x penalty. Measured: the local
rule crosses between 48 and 64; attention crosses between 8 and 16 (g1-04).

    THE PRICE OF LOCALITY IS ROUGHLY 4x TO 6x IN WIDTH.

That is a number worth having. It is not "locality is free" and it is not
"locality is impossible" -- it is a cost, in a unit that can be multiplied by a
machine count and argued about. Note 004's bandwidth arithmetic can now be
re-run against a width that has been measured rather than assumed.


THE FINDING NOBODY PREDICTED, AND IT MATTERS MORE
--------------------------------------------------
*** THE OBSERVATION BELOW STANDS. THE EXPLANATION OF IT IS REFUTED. ***
g1-06 tested this section's account directly. If the graded transition were
superposition interference, the crossing width would grow with the number of
bindings held. It does not: at n_pairs 2, 4 and 8 the crossing sits between 48
and 64 in every case, and at small widths MORE bindings is BETTER -- the opposite
sign. See experiments/sweeps/g1-06-interference.txt. The gradedness is measured
and real; "because interference is continuous" is not why.

Look at the `between` column.

    attention (g1-03):   60 runs, 0 intermediate outcomes. Strictly bimodal.
    this rule:           9 of 48 cells land between stuck and solved, and the
                         transition is smooth: 0.02 -> 0.09 -> 0.22 -> 0.91 ->
                         0.99 -> 1.00 as width doubles.

**The local rule has a slope where backprop had a step.**

The mechanism is not mysterious once stated. Attention has to *discover a
circuit*: either the query/key projections align into a working induction head
or they do not, and that is a discrete event -- which is why g1-03 saw two
outcomes and nothing between. The Hebbian store performs the correct operation
from the first update; it never has to find anything. What limits it is
INTERFERENCE, because every binding is superposed into one matrix and retrieval
returns the right one plus a sum of all the others. Interference falls smoothly
as width grows.

    Circuit discovery is discrete. Superposition interference is continuous.

**This inverts the expectation set in g1-03 and g1-04, and in the project's
favour.** Those notes concluded that a mean is a fiction here and that G1 should
count solved/stuck rather than average. That reasoning was right for attention
and is wrong for this rule: for a graded mechanism a mean is meaningful, and the
whole apparatus of "how close did it get" -- which g1-04 declared malformed --
becomes the right question again for the thing the project actually proposes to
build.

It also bears on docs/notes/002 §4's argument. A predictive objective needs
something to descend. A mechanism whose error falls off smoothly with capacity
gives it one; a mechanism that must find a discrete circuit does not. **The
local rule is better shaped for local learning than the global one was**, which
is not what anyone would have guessed.

Recorded with the caution it deserves: one task, one configuration, one rule.
The claim is about this mechanism on this benchmark, not about locality in
general.


NOT YET TESTED
--------------
Predictions 3 (does the penalty grow with n_pairs) and 4 (does decay help) are
untouched. 3 is the more interesting: attention was completely flat in n_pairs
across 56 runs, and superposition interference should not be, which would make
n_pairs a real difficulty dial for the first time -- for exactly the reason it
was not one before.


COST NOTE
---------
48 cells in ~2 minutes wall clock on Actions, against a local attempt that was
projected at 30+ minutes and had to be killed for consuming the machine. The
matrix is per (seed, width) rather than per seed so the expensive d_model=96
cell -- ~19x the cheapest -- does not set the wall clock for everything else.
