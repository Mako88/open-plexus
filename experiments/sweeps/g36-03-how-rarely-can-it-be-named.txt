How rarely can a thing be named and still be grounded?
======================================================

Script: experiments/g36_03_how_rarely_can_it_be_named.py
Status: RUN, local, 2026-08-01, 11.2s. Predictions committed at `3e8901a`
        before the script was executed.

ANSWER: **naming is NOT as cheap as the occasion threshold implies, and P2 is
        refuted.** At 16 namings per code — `g32-02`'s measured threshold — link
        purity is **0.7847**, not the predicted 0.90. Below that it falls off a
        cliff: **0.3596** at 8 namings and **0.0664** at 1.6, which is BELOW
        chance. Grounding a name costs more evidence than learning a concept
        does.


IN PLAIN TERMS
--------------
`g36-01` had the word present every single time a picture was shown. That is not
how naming works. A child sees dogs constantly and hears the word *dog*
occasionally — most sightings are silent.

So: show the pictures as before, and speak the word only some fraction of the
time. How rare can the naming get before the link breaks?

**This is also as close to gate G7 as this setup can honestly get**, and the
reason is worth stating because it locates something.

The strict reading of G7 would be: can the word reach a picture-code it has
*never* been spoken alongside? **In this stream that is impossible for a
structural reason** — each moment shows one picture, so picture-codes never
appear together, and there is no chain from an unnamed code to a named one. A
test of it would fail for bookkeeping reasons and tell us nothing.

Which makes clear where generalisation actually lives in this design:

  - **Seeing a new three as a three** is the quantiser's job. A fresh picture
    lands on the code the existing threes already occupy — that is why the code
    exists.
  - **Knowing that code is called "three"** is co-occurrence's job.

So the honest question is whether naming a *fraction* of a code's pictures is
enough to name the whole code. And there is already a number that predicts the
answer: `g32-02` measured about **16 occasions** as what a concept needs. A code
here holds about 80 pictures, so naming should break somewhere near a rate of
**0.20**.


WHAT IS BEING MEASURED
----------------------
Identical to `g36-01` except for the naming rate, so the two are directly
comparable and the rate is the only thing that moved.

    quantiser   agreement WITHIN a modality. **Unaffected by naming** and
                reported as the control it is: if it moves, something other than
                the intended axis changed
    link        of the image codes a word reaches, the share whose majority is
                that word's digit. Per CODE
    grounded    share of ALL images both reachable from their word and in a
                majority-correct code. Per IMAGE, so it is comparable with
                `quantiser` where `link` is not — the confound `g36-01` had to
                correct
    reach       share of the ten words reaching any image code
    classes     mean recovered class size, the collapse companion

Chance for the purities is the largest class share, about 0.11.


MEASURED ON
-----------
Local, single process, Python 3.14, numpy for the quantiser only.

    images       4,000    MNIST prefix, ~80 per code
    codes           50    `g36-01`'s operating point: perfect link purity there
    words           10
    noise            2    other words, carried from g36-01
    distractors      1    carried
    quantiser  spherical k-means over unit pixel rows
    bound      derived
    seeds      0, 1, 2

Swept: naming rate in {0.02, 0.05, 0.10, 0.20, 0.50, 1.00} — about 1.6, 4, 8,
16, 40 and 80 namings per code.

**The grid brackets the predicted breaking point on both sides**, which
`g33-01` did not do for bucket width and had to say so afterwards.


PREDICTIONS
-----------
P1  CONTROL. `quantiser` is flat across every naming rate, because the clustering
    never sees a word.
    REFUTED IF it moves, which would mean the naming rate is reaching something
    it should not and no other row is interpretable.

P2  NAMING IS CHEAP. At a rate of **0.20** — about 16 namings per code, which is
    `g32-02`'s measured threshold — `link` is still above 0.90.
    REFUTED IF it has already collapsed there, which would mean grounding needs
    far more naming than a concept needs occasions, and the two thresholds are
    not the same quantity.

P3  IT BREAKS BELOW THAT, AND SHARPLY. At 0.05 — about 4 namings per code —
    `link` falls below 0.50 and `reach` falls below 1.0, because some words never
    accumulate enough evidence to rank their own code first.
    REFUTED IF it survives at 0.05, which would be the better outcome: naming
    would be cheaper than the occasion threshold implies, and the word would be
    getting help from somewhere this file has not accounted for.

P4  `grounded` FALLS FASTER THAN `link`. `link` asks whether the codes a word
    reaches are the right ones; `grounded` asks how many images that covers. A
    word that reaches one correct code out of its digit's three scores perfectly
    on the first and poorly on the second.
    REFUTED IF they fall together, which would mean a digit's images are
    concentrated in a single code and the quantiser is doing more than
    `g36-01`'s 0.83 purity suggests.

SCORECARD
---------
  P1  HELD, exactly. `quantiser` is **0.8299** at every naming rate, to four
            decimals, because the clustering never sees a word. The naming rate
            reaches nothing it should not.

  P2  REFUTED. At 0.20 — 16 namings per code, which is `g32-02`'s measured
            threshold for a concept — `link` is **0.7847**, not above 0.90.

            **So the two thresholds are not the same quantity**, which is what
            the refutation clause said it would mean. Learning that a set of
            pictures belong together takes about 16 sightings; learning what that
            set is CALLED takes more. The naming has to out-compete the noise
            words, which are present at two per occasion regardless, so a rare
            name is fighting a constant distractor rather than merely being
            scarce.

  P3  HELD. At 0.05 — 4 namings per code — `link` is **0.1272**, far below the
            predicted 0.50, and `reach` falls to **0.9667**: a word that is
            almost never spoken fails to reach any picture at all.

            At 0.02 it is **0.0664**, which is BELOW chance 0.1110. A word spoken
            1.6 times per code does not merely fail to ground — it grounds to the
            WRONG codes, which is the raw-counting failure of `g32-01` arriving
            through scarcity instead of through frequency.

  P4  HELD, and the gap is large. `grounded` falls much faster than `link` —
            0.7877, 0.6346, **0.3307**, 0.1303 against 0.8084, 0.8929, 0.7847,
            0.3596. At 0.20 a word reaches mostly-correct codes (0.78) covering
            only a third of its images (0.33).

            So a digit's pictures ARE spread across several codes, as the 0.8299
            quantiser purity implies, and a rarely-named word reaches some of
            them and not the rest.


THE ROW THAT DID NOT MATCH, AND WHAT IT COST
----------------------------------------------
`naming` 1.00 is `g36-01`'s configuration and should reproduce its **1.0000**.
It gives **0.8084**.

The streams are not byte-identical — testing `rng.random() < naming` consumes a
draw that `g36-01` does not, so the noise words differ — but a seed difference
producing 1.0000 against 0.8084 is too large to accept without checking.

**Checked, and `g36-01`'s headline was a lucky draw.** Eight seeds of that cell:

    1.0000  1.0000  1.0000  0.7015  1.0000  0.9773  1.0000  1.0000

Mean **0.9599**, worst **0.7015**. `g36-01` used seeds 0, 1 and 2 — the project's
convention — and all three are clean. **A failure in one draw of eight is missed
by three seeds about two thirds of the time**, so a clean sweep of three is the
expected outcome even when the failure exists.

`g36-01`'s record is corrected and the claim of perfection withdrawn; the finding
itself is untouched, because 0.96 against chance 0.111 was never resting on the
last four decimals. The standard is now in `CLAUDE.md` rule 3: **whenever a cell
returns a perfect score, run more seeds before writing the word "every".**


WHAT THIS DOES NOT SETTLE
--------------------------
**Why naming is dearer than occurrence.** The account above — a rare name
competing against constant noise words — is an explanation offered, not measured.
Sweeping `noise` at a fixed naming rate would test it and is not run.

**Whether a better quantiser moves the cliff.** `grounded` is capped by
quantiser purity, and at 0.8299 a third of the shortfall at high naming rates is
the front end rather than the linking.

**And nothing here is distributed.** One process, no join.
