The price of dropping the global readout
========================================

Script: experiments/g4_01_partitions.py
Status: PREDICTIONS WRITTEN, NOT YET RUN


IN PLAIN TERMS
--------------
Everything measured so far had one shared scorer at the end: all the machines'
work funnels into a single place that produces the answer. That is exactly the
everybody-waits-for-everybody step this project exists to avoid, and it was in
there the whole time because the benchmark wants one answer per question.

So now each machine gets its own scorer, learning from its own mistakes only.
Nobody consults anybody. Each machine produces a complete answer by itself.

Two things to find out. How good is ONE machine's answer alone -- because if it
is good enough, the shared step is optional rather than required. And how much
worse is the whole thing than the version with a shared scorer -- because that is
the price, and it is a price worth paying only if it is small.


QUESTION
--------
Split the width into P contiguous groups, each with its own readout over its own
dimensions, each learning from its own prediction error. Measure:

  POOLED    argmax of the summed group answers -- what a deployment does when it
            can afford one vocab-sized reduction at query positions
  ALONE     argmax of one group's answer -- what a machine sees when it cannot

  width      32, 64, 128
  P          1, 2, 4, 8
  seq_len    96, 384
  lr         0.02, 0.05, 0.1     <- swept on EVERY arm, not just the new one
  seeds      1, 2, 3
  budget     16 epochs, checkpointed at 4 and 8

24 jobs, 9 runs each. lr is swept across all P because P changes the error term
and lr and the error term are not independent -- and because a hyperparameter
swept on one arm of a comparison has to be swept on all of them, which is a rule
this project earned from g3-02 and paid for again in g1-11.


THE STRUCTURE THAT MAKES THIS NON-OBVIOUS
------------------------------------------
A group is NOT a narrow model. Group g owns rows R_g of the memory, so it has
d/P retrieved features -- but each of those features is an inner product over the
FULL d-dimensional key. The addressing resolution stays at d; only the number of
features shrinks.

That is the whole reason to expect this to work at all, and it is the difference
between "each machine is a small model" (which would be hopeless) and "each
machine is a narrow view of a large model" (which might not be).


PREDICTIONS -- written before the run
--------------------------------------
1. **ALONE at P groups beats the standalone model of width d/P.** g1-13 measured
   standalone local accuracy at seq_len 96: d=16 gives 0.559, d=32 gives 0.974.
   So one group of a P=4, d=64 model -- 16 features, 64-dimensional keys -- should
   come in above 0.559.

   If it lands ON 0.559 instead, feature count is the binding constraint and
   addressing resolution is free, which is a different and more pessimistic
   world.

2. **POOLED beats ALONE at every P > 1.** Each group independently drives its own
   output toward the target, so pooling is an ensemble of estimators whose errors
   are not identical. If pooling does NOT help, the groups have converged on the
   same function and the partition is buying redundancy with no diversity.

3. **POOLED at P > 1 is worse than P = 1 at the same total width, and the gap
   grows with P.** With one readout, feature j's weight is fitted knowing what
   the other d-1 features contribute; partitioned, each group redundantly fits
   the whole target from its own slice. Cooperation should beat redundancy at a
   fixed budget. Guess at d=64, seq_len 96: 0.999, 0.99, 0.97, 0.90.

4. **The gap is larger at seq_len 384 than at 96,** because there is less
   headroom everywhere at 384 (g1-13: d=64 gives 0.999 at seq 96 and 0.994 at
   384, with the whole curve below it much steeper).

Most likely to be wrong: (3). Ensembling is a strong effect and a single global
error term can have groups cancelling one another, so partitioned pooling being
EQUAL to or BETTER than P=1 is a live possibility.

**That is the favourable direction, so it gets the g1-12 treatment.** If P > 1
wins, check before believing:

  - that it is not an effective-learning-rate artefact -- P groups each apply a
    full-size update, so the total weight change per step differs. Early in
    training y is near zero and both rules reduce to lr * target (x) r, so a gross
    scaling difference is not expected -- but "not expected" is what g1-11 said.
    The lr sweep exists to catch it, and the check is whether P>1 wins at its
    OWN best lr against P=1 at ITS own best lr, never at a shared one.
  - that P=1 has converged. It is the arm that would be losing, so it is the arm
    that would be under-measured, which is the exact shape of every previous
    error in this project.


WHAT WOULD REFUTE WHAT
-----------------------
- ALONE is near chance at every P     -> a single machine cannot answer, the
                                         pooling step is mandatory, and note 009
                                         §4's argument fails. G4 needs a
                                         different decomposition
- ALONE is usable, POOLED costs
  little                              -> the global readout was scaffolding, as
                                         claimed. C1 survives at the readout
- POOLED collapses as P grows         -> the price of dropping the readout is
                                         real and scales with machine count,
                                         which bounds G5 directly
- P>1 beats P=1                       -> suspicious. Run the two checks above
                                         before writing it down


WHAT THIS DOES NOT SETTLE
--------------------------
Nothing here is distributed. It is one process computing what P machines would
compute, exactly as G1 was before G2 and G3 tested it. Delay and churn against a
partitioned readout are separate questions, and the churn one already has a known
complication: a departing machine takes a slice of the shared key with it, so it
degrades every surviving group and not only its own.
