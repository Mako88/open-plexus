Does our loss fall with DATA the way a backprop model's does?
=============================================================

Script: experiments/g11_04_scaling_exponent.py, with --chars as the axis
Status: DISPATCHED, awaiting results.


IN PLAIN TERMS
---------------
If you give a normal neural network more text to read, it gets better at
predicting text. The question here is whether OUR model does too, and whether it
improves at the same RATE.

That matters more than it sounds. Everything this project has measured is small.
If our model improves more slowly with scale than a normal one, then every
favourable comparison at small scale is temporary and the gap grows for as long
as anyone keeps scaling -- and no amount of measuring at small scale would ever
show it. A "yes, at the same rate" would mean the approach is worth scaling. A
clear "no" is the single result that would say the primary goal is out of reach
by this route.

The previous attempt asked the same question by making the MODEL bigger instead
of the data larger, and could not answer it -- see below.


WHY THIS RE-RUN EXISTS
-----------------------
g11-04 swept WIDTH at 250,000 characters and was inadmissible: the backprop
control fitted b = -0.0021 with an R2 of 0.13, flat. A reference that does not
move cannot be compared against.

**The cause was the cap itself.** The baseline reaches 4.20 bits by width 16 and
does not improve, because 250,000 characters is not enough text for a wider
attention model to have more to learn. It was data-limited, not width-limited.
And 250,000 was exactly the cap introduced to stop g11-04 timing out the way
g11-03 had -- so the fix for the cost problem removed the phenomenon the
experiment was built to measure.

Data is also the axis Filipovich et al. (arXiv:2210.14593) actually used, so
this is the closer replication of the result being tested against.

**One connection defect had to be fixed before this could run at all.**
`TRAIN_CHARS` was a module constant, and `--cap` -- the flag whose name suggests
it -- is the memory store's norm cap, unrelated to the corpus. A sweep passing a
data axis today would have run five identical cells and reported a flat
exponent, which is indistinguishable from the real thing. `--chars` is new, and
tests/test_data_axis.py is the connection test.


PREDICTIONS
------------
Registered before dispatch. No pre-dispatch control has been run on this axis,
so unlike g7-04 these are commitments rather than summaries. The only prior
information is g11-04's 250k column, which is one point of the five.

  P1  THE CONTROL FIRES. The backprop arm has a clearly negative exponent on
      data, |b| > 0.02. This is the admissibility test and it is the one that
      failed last time. If it fails again the range is still wrong and nothing
      else here may be read.

  P2  BOTH OUR ARMS IMPROVE WITH DATA, |b| > 0.02. This is a genuine prediction
      rather than a safe one: on WIDTH our arms were flat or nearly so, and note
      035 explains why (the store is a bigram table of effective rank ~3, so
      width buys nothing). **No such argument protects the data axis.** More
      text means better bigram statistics, and our model is at 5.49 bits while
      an actual bigram model reaches 3.583 -- so there is a large amount of
      headroom that is not blocked by the rank result.

  P3  OUR ARMS ARE SHALLOWER THAN BACKPROP. This is the Filipovich shape and the
      bad outcome for the project.

  P4  THE SINGLE-TOKEN ARM FLATTENS AT THE TOP OF THE RANGE while the context
      arm does not. Its ceiling is a bigram and more text cannot move a ceiling;
      the context arm's ceiling is a trigram, which has more to absorb. This is
      the prediction that distinguishes "the rule cannot use more data" from
      "this arm has run out of ceiling", and those two have opposite meanings.

WHAT WOULD REFUTE EACH: P1 by |b| < 0.02 on backprop. P2 by either of our arms
flat. P3 by one of our arms matching or beating backprop's exponent. P4 by the
two arms having the same curvature at the top of the range.

**P2 and P4 can both be true, and that combination is the informative one:** it
would say the rule uses data fine and the single-token architecture is simply
finished, which points at the ceiling rather than at local learning.


COST
-----
15 jobs: 5 data points x 3 arms, two seeds inside each on 2 workers, width fixed
at 64, chunk 128, 300-minute timeout.

    chars      62,500  125,000  250,000  500,000  1,000,000

Measured locally at 20,000 characters, width 64, per seed:

    single     12.77s      context    12.69s      backprop    1.79s

Cost is linear in chars, so the MOST EXPENSIVE CELL -- which is the one to
estimate from, per g11-03 -- is `single`/`context` at 1,000,000 characters:
about 640 seconds per seed locally, and the two seeds run on two workers, so
roughly 11 minutes of wall clock. At a 3x allowance for a slower hosted runner
that is ~33 minutes against a 300-minute timeout. The backprop arm is an order
of magnitude cheaper and is not a risk at any cell.

Summed across all 15 jobs the matrix is about 44 minutes of local-equivalent
job time, so on the order of 110 hosted runner-minutes, with a wall clock set by
the longest job rather than the sum. g11-04 was 48 minutes of wall clock for 12
jobs, so this is the same order and not a step up.

**Width is pinned at 64, and that value comes from g11-04's grid, where all
three arms were measured at 250,000 characters:** backprop 4.157, context 5.759,
single 5.505. The 250,000 cell of this sweep therefore has a published value to
land on, and disagreement there is a dispatch or identity error rather than a
finding. Naming where a pinned value came from is the habit note 028 bought.


MEASURED ON
------------
Tiny Shakespeare, 64 symbols, 1,003,854 training characters available -- so the
top of the range uses essentially all of it and the axis spans 16x. The script
refuses rather than truncating if a cell asks for more than the corpus holds,
because a silently truncated top cell collapses the last points onto one value
while the summary still prints the requested one.

80/20 fit/calibration split WITHIN the capped stream, so both grow with the
axis. Tested on the corpus's held-out tail, which is the same text at every
point on the axis -- pinned by a test, since an exponent fitted through a moving
test set is fitted through two things at once.

Temperature fitted on held-out training text for our arms; the backprop arm's
logits are used raw, since fitting a temperature for it would flatter it.
