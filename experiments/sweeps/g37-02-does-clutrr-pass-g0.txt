Does CLUTRR-symbolic pass G0, and where does our rule land on it?
==================================================================

Script: experiments/g37_02_does_clutrr_pass_g0.py
Status: RUN, local, 2026-07-31. Predictions committed at `0ce95a4` before the
        script was executed.

ANSWER: **G0 is NOT ANSWERED, and that is different from FAILED.** Every learning
        arm lands below the floor at every depth past 3 hops. The registered
        response to that was a width/epoch probe on the reference, and it ran
        (`g37-03`): **train accuracy is 0.4185 at d128x16 and 0.4215 at
        d256x48** — twice the width and three times the epochs buy **0.003**.
        The reference cannot fit data it has seen forty-eight times, so it is not
        undertrained, it is structurally unable to compose. **These numbers are a
        statement about `ShiftedAttention`, not about CLUTRR.**

        And a second correction, upstream: `g37-01` called the test bucket's
        majority share "the honest floor". **It is an ORACLE floor.** A constant
        predictor fitted on TRAIN answers `brother`, which appears **0 times** in
        the 2-hop and 3-hop test buckets. See below — the record is corrected
        there too.


IN PLAIN TERMS
--------------
The project keeps a short list of things that could kill it. Item one asks
whether training a system on *relationships between things* actually buys it the
ability to reason, rather than just to remember.

That question has been unanswerable because there was no test sensitive enough.
The previous run found one — CLUTRR, somebody else's published benchmark, whose
data has been sitting in this repository the whole time — and established that
the gap between "learned nothing" and "best published result" is wide.

**A wide gap means the test can SEE a difference. It does not mean we will like
the direction.** This run is the check that has to come before any of that.

It asks two things.

**First, is the test actually hard?** If a system with random, untrained
internals already scores well, then the task can be done without learning
anything, and every result measured on it afterwards is meaningless. That is
exactly the mistake the predecessor project made, and it cost about a year.

**Second, is the test actually possible?** A model given every advantage — real
gradient training, the whole sequence to look at — is run on it. If even that
cannot do it, the task is not learnable in this framing and nothing built on top
is worth running.

Only if the first fails and the second succeeds is there room in between for a
learning rule to be judged. Our own rule is run too, so we find out where it
lands — and there is a live possibility, already seen once on the test we built
ourselves, that it lands **below** the score you would get by always guessing the
same answer.

The puzzles get harder in a specific way: the system is trained only on short
chains and tested on chains up to five times longer. So the numbers are reported
per chain length and never averaged, because the short ones are memory and the
long ones are the actual question.


WHAT IS BEING MEASURED
----------------------
Accuracy at the query slot: the relation the puzzle asks for, which is never in
the stream. Reported **per hop bucket, never pooled**, with each bucket's own
floor beside it.

    majority    always answer the commonest relation IN TRAIN. The base rate.
                Taken from train and not test, because a constant fitted to the
                answers is not a floor, it is a one-parameter model
    frozen      our model, random `Wo`, NO LEARNING. The substrate
    local       our model under the delta rule. The candidate
    attention   backprop, softmax over positions, Adam. The strong reference

**Two axes must not be averaged over and the script refuses to.** Hops 2-3 are
the ONLY depths in train, so they are recall and 4-10 are generalisation.
And `g37-01` measured the floor MOVING with entity repetition in the unhelpful
direction — 0.3810 against 0.2336 at 6 hops — so `clean_accuracy` is recorded
per bucket rather than pooled into a second headline.


MEASURED ON
-----------
Local, one process.

    data          CLUTRR gen_train23_test2to10, fetched, gitignored
    layout        kinship -- chosen on measurement, collisions 35.9% -> 7.7%
    train         9,074 puzzles, hops 2-3 ONLY
    test          1,146 puzzles, hops 2-10
    relations     20 in the fixed vocabulary; 18 used as answers
    local         d256, pair keys, one hop, NO search, 4 epochs
    attention     d128, Adam lr 3e-3, 16 epochs
    seeds         0, 1, 2

**Search is OFF in the local arm deliberately.** This measures the OBJECTIVE, and
mixing in the search mechanism would make a result unattributable to either.

**THE FULL TRAIN SPLIT IS USED, and that was a measurement rather than a
choice.** The cost probe put the expensive arm at **1.68 ms** per training
sequence, so all 9,074 puzzles cost 12.2 minutes across three seeds. `g14-01` had
to cap `closure` at 300 because its sequences are 120 tokens; CLUTRR's are 11 to
43. A subsample would have needed its size defended and buys nothing.

**THE ATTENTION SETTINGS ARE CARRIED FROM `g14-01`, WHERE THEY WERE CHOSEN FOR A
DIFFERENT TASK.** d128 and 16 epochs were tuned on `closure` at 120 tokens.
`CLAUDE.md`'s calibration is explicit that naming a carried constant as a risk
does **not** prevent it — g9-11 did exactly that and lost 0.58 anyway. So this is
recorded as the standing risk of this run, and P2's refutation clause below says
what to do if it fires, rather than leaving it to be discovered.

**The data does not move with the seed.** CLUTRR is a fixed file; seeds vary
model initialisation and training order only. Spread here is a statement about
the model and not about the task, and it will be narrower than `g14-01`'s.


PREDICTIONS
-----------
P1  THE TASK IS NOT ANSWERABLE WITHOUT LEARNING. `frozen` sits at or below the
    floor in every bucket, and does not exceed it by more than 0.05 anywhere.
    REFUTED IF `frozen` clearly beats the floor. **That is the predecessor's
    failure exactly** — a random substrate that already composes means the
    instrument cannot attribute anything to learning, and CLUTRR would have to be
    discarded despite its band.

P2  THE TASK IS LEARNABLE AT ALL. `attention` beats the floor by more than 0.15
    in the IN-DISTRIBUTION buckets, hops 2 and 3.
    REFUTED IF it does not. **Then the first thing to check is the carried
    constants, not the task**: d128 and 16 epochs came from `closure`, and
    `g14-01` reported that task failing G0 at an undersized reference before the
    reference was fixed. The response to a refutation here is a width/epoch probe
    on THIS task, and only a second failure would say anything about CLUTRR.

P3  **THE GATE.** Headroom at 4+ hops — `attention` minus `frozen` — exceeds 0.15
    in at least three of the seven out-of-distribution buckets.
    REFUTED IF it does not. Then the band `g37-01` computed is real but
    unreachable by anything this project can run, and item #1 goes back to
    blocked with a *different and better* reason than the one it had.

P4  SYSTEMATIC GENERALISATION IS HARD, WHICH IS WHAT CLUTRR IS FOR. Every
    learning arm declines from hops 2-3 to hops 9-10, and `attention` at 10 hops
    is below its own score at 3 hops by more than 0.20.
    REFUTED IF accuracy is flat across depth. That would mean either the model
    generalises perfectly — implausible against the published references, which
    all decline — or the query is answerable without following the chain, which
    would be a defect in how this script frames the task and would invalidate
    every other row.

P5  `local` LANDS BETWEEN `frozen` AND `attention`.
    REFUTED IF it is below `frozen`, or above `attention`. **The first is a live
    possibility and is not a formality**: on `closure`, `local` scored 0.108
    against a majority floor of 0.190 on every one of eight seeds — actively
    mispredicting, worse than having learned nothing. If that repeats here on
    somebody else's benchmark, it is the strongest negative result this project
    has produced and it belongs in the record as one.

P4 is the rail. If it fails, the task is not being posed as intended and P1-P3
are unreadable whatever they say.


COST
----
Measured, not estimated. The cost probe reports **1.68 ms** per training sequence
for the expensive arm, giving **4.1 min** per attention cell and **12.2 min**
for three seeds. `majority` and `frozen` are nearly free; `local` trains without
a backward pass. **Total expected: 15 to 25 minutes**, local, no runner.

Recorded after the run: about **20 minutes** for the matrix, inside the 15-25
estimate, plus **17 minutes** for the follow-up probe that was not budgeted for
because it was contingent.

**TWO FLOORS, AND THE DIFFERENCE IS THE MOST IMPORTANT LINE IN THIS FILE.**

  `majority`   what a constant predictor fitted on TRAIN actually scores. It
               answers `brother`, the commonest train target at 0.1087.
               **ACHIEVABLE.** 0.0000 to 0.1092
  `oracle`     the commonest answer in each TEST bucket. **NOT achievable** — a
               model would have to know the test labels to choose it. 0.1370
               overall, up to 0.5000

`g37-01` computed the second and called it the honest floor. That was wrong and
is corrected in its own record. **The gap between them is a property of CLUTRR
and it is large**: `brother` appears **0 of 38** times at 2 hops and **0 of 105**
at 3 hops, while those buckets are 50.00% `grandson` and 42.86% `father`. At 4
and 10 hops the commonest test answer is `niece` — **one of the six relations
that never appear as a stated edge**, only as a target.

So the train and test answer distributions are not merely different, they are
close to disjoint at the shallow end.


SCORECARD
---------
  P1  **HELD, and more strongly than intended.** `frozen` scores **0.0000** in
            every bucket across three seeds. The task is certainly not answerable
            without learning.

            **But it is a floor the way a wall is a floor**, which is `g14-01`'s
            phrase for the identical observation on `closure`. A random `Wo`
            emits a token that is essentially never a relation at all — the
            vocabulary is 33 tokens of which 20 are relations — so this measures
            "an untrained readout emits noise", not "the task resists a
            non-learner". **`majority` is the floor that means something.**

  P2  **REFUTED.** `attention` scores 0.1667 and 0.3651 at hops 2 and 3, against
            an oracle floor of 0.5000 and 0.4286. It is below the oracle floor
            in-distribution, on the depths it trained on.

            **The registered response was to check the carried constants before
            saying anything about the task, and that is what happened.** `g37-03`
            swept width and epochs:

                d128 x16   train 0.4185
                d128 x48   train 0.4205
                d256 x16   train 0.4185
                d256 x48   train 0.4215

            **Twice the width and three times the epochs move training accuracy
            by 0.003.** A model that cannot fit 2,000 examples it has seen
            forty-eight times is not undertrained.

            So the refutation is real and its cause is identified: **a
            single-layer shifted-attention model cannot compose a chain of
            relations.** It was built for MQAR-style single-hop recall and that
            is what it does. Composing two hops needs a second pass and the
            architecture has none.

            **This is a negative result about our own tooling, not about
            CLUTRR.** Every published reference on this benchmark — R5, CTP, GAT
            — is a multi-hop architecture.

  P3  **REFUTED, and UNREADABLE, which is the honest verdict.** Headroom at 4+
            hops is 0.10, 0.07, 0.065, 0.07, 0.073, 0.053, 0.064 — under 0.15 in
            all seven. But P3 measures `attention` minus `frozen`, and P2
            established that `attention` is not a strong reference on this task.
            **A gate computed from a broken reference is not a verdict.**

            `GOALS.md` G0 requires a strong non-local reference **measured**. This
            project does not currently have one that can compose. That is the
            finding.

  P4  **HELD, and it is the rail, so the rest is readable.** Every learning arm
            declines with depth. `attention` goes 0.3651 at 3 hops to 0.0644 at
            10, a fall of 0.3007 against a predicted floor of 0.20. `local` goes
            0.3492 to 0.0868.

            So the task IS being posed as a composition problem — depth costs
            accuracy, which is what CLUTRR exists to show and what every
            published reference also shows. Had this been flat, everything above
            would have been unreadable.

  P5  **HELD, narrowly and unimpressively.** `local` sits above `frozen`
            everywhere and above `attention` in six of nine buckets — 0.5000
            against 0.1667 at 2 hops, 0.0868 against 0.0644 at 10.

            **Beating the reference is not a good sign here.** It means the two
            are close together near the bottom rather than that the local rule is
            strong, and P2 established the reference is not measuring what it was
            meant to. The one thing worth keeping: `local` is at the oracle floor
            at 2 hops (0.5000) and above `majority` everywhere, so unlike
            `closure` it is not actively mispredicting.


WHAT THIS CHANGES
-----------------
**Item #1 is not re-blocked, and the blocker has moved to a more tractable
place.** Before today it was *"no instrument with a wide enough band"*. After
`g37-01` the instrument exists and the band is real. After this run the missing
piece is **a reference model capable of multi-hop composition**, which is a thing
to build rather than a thing to find.

**Three ways forward, and they are not equal.** Building a composing reference is
the one `GOALS.md` asks for and is the only one that yields a measured band.
Quoting the published numbers is cheaper and leaves G0 formally unmet. Declaring
CLUTRR too hard is not supported by anything measured here.

**And the achievable floor is LOWER than reported**, which makes the band wider
rather than narrower: against `majority` at 0.0588 to 0.1092, published
references at 0.39 to 0.97 leave 0.28 to 0.91.


WHAT THIS DOES NOT SETTLE
-------------------------
**Nothing about whether a relational objective buys reasoning**, which is what
item #1 asks. That comparison needs a reference first.

**The local arm's settings were never tuned on this task either.** d256 and 4
epochs are carried from `g14-01`. `CLAUDE.md` requires a hyperparameter swept on
one arm to be swept on all, and `g37-03` swept only the reference. **So `local`'s
numbers here are provisional in exactly the way the reference's were**, and it
would be inconsistent to treat them as settled while correcting the other.

**The train/test answer shift is unexplained.** `brother` appearing 0 times in
two test buckets is recorded, not diagnosed. It may be intrinsic to how CLUTRR
generates longer chains, or it may interact with the `kinship` layout choice.
