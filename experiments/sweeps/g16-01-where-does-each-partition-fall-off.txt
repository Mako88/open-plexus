At fixed per-node memory, where does each way of splitting the store fall off?
==============================================================================

Script: experiments/g16_01_where_does_each_partition_fall_off.py
Status: RUN locally, 5 seeds, all 50 cells. Pure numpy, no training, no task --
        the same shape as decision 109's probe, which this rebuilds because that
        one was inline and left no script.

ANSWER: **POOLED CAPACITY IS IDENTICAL. LONE-NODE CAPACITY IS NOT, and that is
        the entire argument for concept partitioning.**


RESULTS
-------
5 seeds, per-node memory held equal at ~4,096 numbers in both arrangements.

  arrangement nodes    pooled     ALONE   node sees
  concept     1           128       128   64 of 64 dims
  concept     2           256       256   64 of 64 dims
  concept     4           512       512   64 of 64 dims
  concept     8          1024      1024   64 of 64 dims
  concept     16         2048      2048   64 of 64 dims
  dimension   1           128       128   64 of 64 dims
  dimension   2           256       141   45 of 91 dims
  dimension   4           512       128   32 of 128 dims
  dimension   8          1024       128   22 of 181 dims
  dimension   16         2048       128   16 of 256 dims

**Pooled: the same at every node count.** 128, 256, 512, 1024, 2048 in both.

**Alone: concept scales with the network, dimension does not.** At 16 nodes it is
2048 against 128 -- a factor of SIXTEEN -- and dimension's lone-node capacity is
flat from 4 nodes onward, at exactly what one node could hold by itself.


PREDICTIONS
-----------
Registered in the script before the run.

  P1  CONTROL. At one node the two arrangements are the SAME STORE and must
      agree to within noise -- they differ only in how a store is split.
  P2  Concept capacity grows roughly linearly with node count.
  P3  Dimension capacity grows too, then COLLAPSES once `w/sqrt(N)` drops under
      ~16 dimensions, which at w=64 is N=16.
  P4  At the largest node count, concept beats dimension by more than 2x.
  P5  Neither reaches the sum of its parts exactly, because superposition
      interferes.


COST
----
5 node counts x 2 arrangements x 8 loads x 5 seeds = 50 cells, pure numpy with
no training and no task. The dearest cell writes a few thousand outer products
at width 256 and takes under a second.

**Run locally rather than dispatched**, the same as decision 109's original
probe, because it measures a data structure rather than a model: there is
nothing to train, no corpus to stream and no task to generate. Nothing here is
heavy in the sense the dispatch-only rule is about.


MEASURED ON
-----------
Nothing -- deliberately. Random `(key, value)` pairs written directly as outer
products, no decay, no cap, no learning and no task, so a task's quirks cannot
enter a measurement of the data structure.

Keys are drawn continuously and so are distinct with probability 1. Decision
109 records its first probe sampling keys WITH REPLACEMENT, writing
contradictory bindings and concluding the opposite of the truth -- the tell was
two widths agreeing to three decimals across four loads.

Per-node memory is held equal between arrangements at ~4,096 numbers, which is
what makes the comparison mean anything, and is printed per cell so a reader can
check it rather than trust it.


SCORING
-------
  P1  CONFIRMED. At one node the arrangements agree exactly (128 pooled, 128
      alone). They differ only in how a store is split and there is no split at
      N=1, so a disagreement would have meant the harness was measuring its own
      bookkeeping.

  P2  CONFIRMED. Concept capacity grows linearly with nodes, 128 to 2048.

  P3  REFUTED AS WRITTEN, and the truth is starker. It predicted dimension
      capacity would grow and then COLLAPSE once `w/sqrt(N)` fell under ~16
      dimensions. **Pooled capacity never collapses -- it grows identically to
      concept.** And lone-node capacity never GROWS: it is 128 at one node and
      128 at sixteen, flat rather than collapsing.

      So the floor is not a cliff the arrangement falls off at some node count.
      **A lone node under dimension splitting is stuck at one node's worth,
      however large the network gets.**

  P4  CONFIRMED, on the lone-node measure: 2048 against 128 at 16 nodes, 16x.
      **REFUTED on the pooled measure**, where they tie exactly -- and reporting
      only the pooled number would have said concept partitioning buys nothing.

  P5  REFUTED. Concept capacity is exactly N times one store's, with no
      interference penalty at all -- because the stores are INDEPENDENT. The
      prediction assumed superposition across nodes; there is none, which is the
      point of the arrangement.


TWO CORRECTIONS TO MY OWN REASONING, BOTH BEFORE THE RESULT
-------------------------------------------------------------
1. **The capacity argument in note 043's first version was wrong.** It claimed
   concept partitioning is the only proposal that adds capacity as the corpus
   grows. At equal per-node memory both arrangements scale the same, and this
   run confirms it exactly. Corrected in the note before this ran.

2. **The first version of THIS PROBE measured the wrong thing.** It reported
   pooled capacity only, and pooled capacity is identical -- so it would have
   concluded that the two arrangements are equivalent and there is no reason to
   build anything. The lone-node measure was added after reading that output and
   noticing it could not distinguish them.

**g4-01 is what said to look there**: it measured a lone node at 0.949 with 16
dimensions, 0.681 with 8 and 0.412 with 4, and amended C1 is about not needing a
collective. A read that requires every node is the barrier the constraint
forbids, so "what can one node do" is the question, not "what can all of them do
together".


WHAT THIS SETTLES
------------------
**Concept partitioning's case is not capacity, it is INDEPENDENCE.**

    pooled capacity      identical -- no argument either way
    lone-node capacity   16x at 16 nodes, and the gap grows with the network
    a read               one node instead of all of them (C1)
    concurrency          a subset of concepts is a subset of nodes
    churn                WORSE per concept -- needs replication

Under dimension splitting, growing the network makes every node's view thinner
while the total stays the same, so a node can never answer alone no matter how
large the system gets. Under concept splitting a node owns whole concepts, so its
standalone capability grows with the network.

**That is a capability difference, not an engineering one**, which is what this
probe was run to find out.


WHAT IT DOES NOT SETTLE
------------------------
Whether the model can LEARN through a concept-partitioned store. This measures
what the data structure can hold, with random keys, no decay, no cap and no task.
Decision 133 is the standing reminder: the last mechanism that looked obviously
right moved the level and not the slope.

And routing does not exist. Deciding which node owns a key is consistent hashing,
which GOALS section 6.2 has listed as unread since the project began.
