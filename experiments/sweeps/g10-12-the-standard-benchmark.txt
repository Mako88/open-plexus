The model on a standard benchmark
=================================

Script: experiments/g10_01_first_language.py --corpus shakespeare
Status: RUN. Width 64, chunk 256, cap 5.0, one seed. Local.

ANSWER: **5.466 bits per character. It does not beat a unigram.** Knowing only
        how often each letter appears scores 4.829; the model scores 0.64 bits
        worse than that, and 1.88 worse than counting letter pairs.


IN PLAIN TERMS
---------------
This is the first number from this project that can be compared with anyone
else's work, on the corpus everyone uses at this size.

It is bad, and it is bad in a specific way: the model is beaten by a method that
does nothing but count how common each letter is and ignore all context. Adding
the memory makes the prediction WORSE than that.

Tiny Shakespeare, 1,115,394 characters, 64 symbols. 1,003,854 train and 110,925
test, split as a contiguous tail, which is the published convention for this
corpus.


WHY THIS IS WORTH HAVING
--------------------------
Every previous number in this project was relative to something we built
ourselves. **This one is on a scale other people's numbers live on**, and it puts
the distance beyond argument: not "somewhat short of a bigram" but **below the
weakest baseline that exists**, and roughly four bits from a small neural network
that anyone can train in minutes.

It also confirms the notes-corpus reading was not an artefact of using our own
prose. 5.47 here against 5.73 there, on a different text with a different
vocabulary and a different split rule.


WHAT IT DOES AND DOES NOT SAY
-------------------------------
**Does:** the associative store plus a linear delta-rule readout is not a
language model at character level, at this width, on this corpus. That is now
measured against a public yardstick rather than inferred.

**Does not:** say the store is worthless, or that the g9 gating results are
wrong. They are correct about the thing they measured. It says the combination
tested here is far from the task, and
[note 031](../../docs/notes/031-a-design-pass-against-the-goals.md) argues that
the readout -- the only component that learns across sequences -- has never been
varied in any experiment.

**And the ceiling matters more than the gap.** g10-03 measured the model BEATING
within-chunk counting at chunk 64, so it is extracting something. What it cannot
do is carry it: capacity is about `d` items (g10-10, g10-11), the store resets
between chunks, and nothing accumulates across the corpus except the readout.


PREDICTIONS -- REGISTERED BEFORE THE RUN
------------------------------------------
Stated to John before the corpus was fetched: *"right now 5.7 bits/char is only
embarrassing relative to our own bigram; against published work it would be
starkly bad."*

**Confirmed, and the specific form was not predicted.** I expected it to sit
between unigram and bigram. It is below unigram, which is a stronger negative
than anticipated -- the memory is worse than ignoring context entirely.


COST
-----
Minutes, local, one seed, one configuration. **One seed and one width**: the
number is a data point, not a characterisation, and g10-02 measured width 32 and
128 giving the same curve to 0.005 bits on the other corpus.
