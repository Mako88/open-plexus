When a node is lost, which structure degrades better?
=====================================================

Script: experiments/g10_08_which_degrades_better.py
Status: RUN, on the fourth attempt. Width 64, 4 nodes, 40 sequences.

ANSWER: the store loses on BOTH counts -- it ends lower and it falls by a larger
        FRACTION. Note 030's claim that churn favours the dimension-sliced store
        is REFUTED on the only task available. But see WHAT THIS CANNOT SETTLE:
        the task was already known not to discriminate, so this may be the same
        non-discrimination measured a third way.


THE RESULT
-----------
         structure    intact   one node lost     fall   relative fall
  dimension-sliced     0.656           0.469   -0.188            29%
  key-sharded (24)     1.000           0.776   -0.224            22%
   key-sharded (4)     0.267           0.251   -0.016             6%

**The store does degrade smoothly** -- every answer computed from 48 dimensions
instead of 64 -- and the cache loses a quarter of its keys outright. That part of
note 030 was right about the MECHANISM of degradation.

**It was wrong about the outcome, twice over.** The cache ends at 0.776 against
the store's 0.469, and it also falls by a smaller fraction of what it had, 22%
against 29%. "Graceful" was doing no work: the store is not even relatively more
robust here.


PREDICTIONS, SCORED
--------------------
Registered in note 030 and in the script before the run:

1. **"Losing a node from a dimension-sliced store degrades every answer
   slightly."** CONFIRMED as mechanism -- the fall is smooth, not cliff-edged.
2. **"Losing a node from a key-sharded table loses those keys completely."**
   CONFIRMED -- a quarter of cues go to guessing.
3. **The implied conclusion, that this favours the store.** REFUTED on both the
   ending value and the relative fall.

The script registered the arithmetic in advance: a cache at 1.000 losing a
quarter of its keys should land near 0.78. It landed at 0.776.


WHAT THIS CANNOT SETTLE, AND IT MATTERS
-----------------------------------------
**`reward_recall` was already known not to discriminate.**
[g10-07](g10-07-can-a-cache-do-the-gating-task.txt) showed a 48-integer table
answers it perfectly while the store reaches 0.65. A cache that starts 0.34 ahead
will still be ahead after both lose something.

So this does NOT show that dimension-slicing is worse than key-sharding in
general. It shows that **churn does not rescue the store on a task where the
store was already losing** -- which is a weaker claim and the honest one.

**The bind this creates is the useful output.** Churn can only be a meaningful
tiebreaker on a task where the two structures are competitive INTACT. No such
task exists in this project. So the ordering is:

    1. find a task where the superposed store is competitive intact
    2. THEN ask whether it degrades better

Note 030 put churn first because the machinery existed. Machinery existing is not
the same as the measurement being interpretable, and that is the lesson.


FOUR ATTEMPTS, AND WHAT KILLED EACH
-------------------------------------
Recorded because the failure modes were all the same shape and only the last was
caught by a guard rather than by hand.

1. **Untrained readout.** Handed `Network` a model that had never learned, scored
   0.031 -- below the trivial floor. Caught by the floor guard added for it.
2. **Wrong test format.** Trained on `build()` output, evaluated on `dataset()`
   sequences. Same length, same query positions, half the accuracy. Caught by the
   floor guard again.
3. **Wrong width.** `d_model` 32, where the ungated arm really is about 0.25. The
   0.65 quoted everywhere is node width 64. Caught by comparing against a number
   I had written down elsewhere.
4. **`absent` without `leave_at` is silently ignored.** Reported a fall of exactly
   +0.000 and read as robustness. **No guard caught this** -- it took checking
   whether any prediction changed at all, and 0 of 3072 had. Pinned in
   `tests/test_distributed.py`.

The fourth is the one worth remembering: every summary statistic looked
reasonable, and only the raw predictions revealed that a parameter had never
applied.


COST
-----
Minutes, local, one seed. **One seed and one loss pattern** -- losing node 0 of 4
at width 64. The direction is large enough to survive that; the exact numbers are
not values.
