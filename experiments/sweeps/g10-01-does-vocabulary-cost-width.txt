Does a bigger vocabulary cost width, and does it cost log(vocabulary)?
======================================================================

Script: experiments/g10_01_vocabulary.py  (NOT WRITTEN)
Status: PREDICTIONS REGISTERED IN NOTE 020 BEFORE THIS FILE EXISTED, and
        before the script. Nothing measured.


WHY
---
[Note 020](../../docs/notes/020-the-capacity-equation-checked.md) checked this
project's central equation, `SNR = sqrt(d / N)`, against Clarkson, Ubaru & Yang's
capacity analysis. Theorem 20 covers exactly our object -- a bundle of key-value
pairs, asking whether a binding is in it -- and gives

    m = O(n log(d / delta))

with `m` our width, `n` our stored-binding count, and `d` the **universe size**.

**The linear dependence on `n` agrees with the empirical fit.** The `log d` term
does not appear in it at all, because **every sweep in this project has held the
vocabulary at 41 tokens.** The fit could not have seen a logarithm in a variable
that never moved.

That makes this the second instance of "check the frozen axes, not just the swept
ones" -- and unlike the first, which cost a headline, this one was found by
reading.


WHAT IS MEASURED
-----------------
The width at which accuracy crosses a fixed bar, as the vocabulary grows.

  n_keys      32, 128, 512, 2048     the universe, which has never moved
  d_model     8, 16, 32, 64, 128     the width whose crossing point is wanted
  lr          0.02, 0.05, 0.1
  seeds       1, 2, 3

**`n_values` is held at 8 deliberately.** The trivial floor is
`1/n_pairs + (1 - 1/n_pairs)/n_values`, so moving the value alphabet would move
the floor every result is measured against, and a crossing-point comparison
against a moving bar is not a comparison. Growing `n_keys` grows the universe
while leaving the floor at 0.34375 throughout.

`n_pairs` and `seq_len` are pinned, so `N` -- the number of bindings in the store
-- is constant across the grid. **The whole point is to vary `d` with `n` fixed**,
which is the axis the theorem separates and the project never has.


PREDICTIONS -- registered in note 020 before the script existed
----------------------------------------------------------------
1. **Width at fixed accuracy grows as `log(vocabulary)`.** From `n_keys` 32 to
   2048 the universe goes from about 40 to about 2056, a log ratio of
   7.6 / 3.7 = 2.05. Guess: the crossing width rises by **1.5x to 2.5x**.

2. **It does not grow linearly in vocabulary.** A 51x increase in `n_keys`
   producing anything like a 51x increase in required width would mean the
   superposition is not doing the thing the whole architecture assumes, and would
   be much worse news than the note suggests.

3. **It does not stay flat.** Flat means the log term does not apply to this
   variant -- plausible, since Theorem 20 is for MAP-B, which bundles with
   `sign(...)`, while this store is real-valued and closer to MAP-I. That is a
   real possibility and it is the one that would make note 020's 2.9x estimate
   for language vocabularies wrong.

4. **Control:** at every vocabulary there is *some* width in the grid that clears
   the trivial floor, and *some* width that does not. If the whole row clears or
   the whole row fails, the width grid does not bracket the crossing and that row
   says nothing.

Most likely wrong: (1) in its precision. The direction is well supported; the
1.5x-2.5x band is a guess about constants that the theorem does not fix for our
variant.


WHAT WOULD REFUTE WHAT
-----------------------
- width rises ~2x across the range   -> the log term applies, note 020's estimate
                                        stands, and a language-scale vocabulary
                                        costs about 2.9x width before anything
                                        else about language is considered
- width rises much faster            -> superposition scales worse than the
                                        theory allows and the tiny-node claim is
                                        in serious trouble
- width does not move                -> the log term does not apply to a
                                        real-valued store. Note 020's caveat was
                                        the right one and its estimate is
                                        withdrawn


WHAT THIS CANNOT SETTLE
------------------------
**Anything about language.** A 2048-token key alphabet of random symbols is not a
vocabulary in any sense that matters; it shares one property with one. The
corpus benchmark is blocked behind the collapse finding regardless.

**The constant.** Theorem 20 is a sufficiency bound, `O(...)`, for a binarised
architecture. It fixes the *shape* and not the multiplier, so a measured 1.7x or
2.4x are both consistent with it and neither confirms the theorem for this store.
