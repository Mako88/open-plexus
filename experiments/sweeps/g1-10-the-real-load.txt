Is the load sequence length? -- the variable nobody moved
=========================================================

Script: experiments/g1_10_seqlen.py
Status: RUN on Actions, 28/28 cells. PREDICTION 1 HELD -- the crossing grows
        with seq_len. Interference is the mechanism and seq_len is the load,
        after three sweeps moved the wrong variable. PREDICTION 2 REFUTED in
        the good direction: the scaling is sub-linear, exponent 0.37.


IN PLAIN TERMS
--------------
We have now failed twice to explain why our rule needs the amount of room it
needs. We thought it was how many things you ask it to remember. It is not. We
thought it was how many different symbols exist. It is not.

Then we read our own code and found something neither of us had looked at.

The rule stores an association between every consecutive pair of things it sees.
Not just the pairs that matter -- EVERY pair, including all the meaningless
padding. So in a 96-step sequence it is holding 95 associations, of which maybe
four are ones anyone will ask about.

Which explains both failures at once. Asking about four things instead of eight
barely changes anything when the memory is holding ninety-five either way.

So the thing that determines how crowded the memory gets is not what we were
asking about. It is **how long the sequence is** -- and that has been fixed at 96
in every single experiment this project has run, including the ones that
supposedly refuted the crowding explanation.


QUESTION
--------
g1-05 explained the graded transition as superposition interference. g1-06
refuted it by sweeping n_pairs. g1-09 refuted its replacement by sweeping n_keys.

Reading `LocalAssociativeMemory.run` afterwards:

    if previous_key is not None:
        memory += np.outer(value, previous_key)

Every step. So the bindings in memory number seq_len-1, and n_pairs is a small
fraction of them:

    seq_len=96, n_pairs=2   ->  95 bindings, 2 of them relevant
    seq_len=96, n_pairs=8   ->  95 bindings, 8 of them relevant

**The interference account may have been right in mechanism and wrong only in
which variable carries the load.**

Sweep seq_len against d_model at tuned key_scale, holding n_pairs at 4.

  seq_len  48, 96, 192, 384
  d_model  16, 24, 32, 48, 64, 96, 128


PREDICTIONS -- written before the run
--------------------------------------
1. **The crossing grows with seq_len.** The central prediction. If it is flat,
   nothing about the task sets the crossing at all and the honest position is
   that we do not understand our own model.

2. Roughly proportional: d approximately linear in seq_len, by the same
   signal-to-noise argument g1-06 made and had refuted for the wrong variable --
   one wanted binding against seq_len-2 others adding incoherently, so holding
   retrieval quality fixed needs d proportional to the count.

   At seq_len=96 the crossing is 32, so:

       seq_len=48   -> near 16
       seq_len=96   -> near 32   (known)
       seq_len=192  -> near 64
       seq_len=384  -> near 128

   The widths above bracket exactly those four points.

3. If (2) holds, the local rule's memory requirement is **linear in the length of
   what it has to process**, which is a genuinely important number for the
   project: it is the same scaling attention has in state, without attention's
   quadratic time. Worth stating carefully rather than celebrated, because it
   also means the rule cannot process an arbitrarily long stream at fixed width.

4. And a consequence worth flagging before it is measured: if the load is
   seq_len, then **most of the memory is spent on padding**. Only n_pairs of the
   seq_len-1 bindings are ever queried. A rule that could avoid storing bindings
   nobody will ask about would need dramatically less room -- but knowing which
   those are in advance is exactly the problem, and any mechanism that guessed
   would be a form of attention smuggled back in.

Most likely to be wrong: (2)'s exponent again, and this note is explicit that the
project has now predicted three scaling laws from signal-to-noise arguments and
had all three fail. The direction is worth predicting. The exponent is being
stated so it can be checked, not because there is any track record supporting it.


WHAT WOULD REFUTE WHAT
-----------------------
- crossing grows ~linearly with
  seq_len                        -> interference confirmed, load identified, and
                                    the scaling law is the deliverable
- crossing grows sub-linearly    -> better news; the rule scales more gracefully
                                    with stream length than expected
- crossing FLAT in seq_len too   -> nothing about the task sets it. The constraint
                                    is intrinsic to the mechanism, three
                                    explanations have now failed, and the honest
                                    report is that we do not understand it
- crossing grows faster          -> the rule cannot handle long streams and the
                                    distribution story needs rethinking

PREDICTION 1 HELD -- THE LOAD IS SEQUENCE LENGTH
--------------------------------------------------
The crossing moves, monotonically, and it is the first task variable in this
project that does. n_pairs was flat across a fourfold change (g1-06). n_keys was
flat across a sixteenfold change (g1-09). seq_len moves the crossing by 2.2x
across an eightfold change.

**So g1-05's interference account was right about the mechanism all along**, and
three sweeps failed to see it because they were all moving variables that barely
touch the load. The store binds every consecutive pair, so what a query competes
against is `seq_len - 1` other bindings; n_pairs and n_keys change almost nothing
about that count.

That closes a question that has been open since g1-05 and has produced three
wrong answers on the way. The record of those is left in place in g1-05, g1-06
and g1-09 rather than tidied, because the useful part is not the answer but how
long a correct mechanism can look refuted when the wrong knob is being turned.


PREDICTION 2 REFUTED, AND IN THE GOOD DIRECTION
------------------------------------------------
Predicted d proportional to the load -- 16, 32, 64, 128 across the four lengths --
from the signal-to-noise argument: one wanted binding against K-1 others adding
incoherently gives SNR ~ sqrt(d/K), so holding quality fixed needs d ~ K.

Measured: **exponent 0.37**, between a cube root and a square root.

    8x the sequence costs 2.2x the width.

The signal-to-noise argument is therefore wrong, or rather incomplete, for the
fourth time in this project. The most likely reason it is too pessimistic is that
it assumes the interference is random. It is not: keys come from a fixed alphabet
of 32 that recurs in every sequence, so the interference is systematic, and a
TRAINED readout can cancel systematic structure in a way it cannot cancel noise.
That is the mechanism g1-09 proposed for the wrong quantity, and it may be
operating here as a correction to the exponent rather than as the primary cause.

**Recorded as a hypothesis, and explicitly not tested.** This project has now
proposed four mechanisms for this crossing and had three refuted; the appropriate
confidence in a fifth, offered in the same breath as a result, is low.


WHAT THE NUMBER IS WORTH
-------------------------
This is the most practically useful scaling result the project has produced.

  **A locality-respecting associative memory needs width growing as roughly the
  cube root of the stream length it must hold.**

Prediction 3 said a linear law would mean the rule "cannot process an arbitrarily
long stream at fixed width". That remains true -- the width does grow -- but at
0.37 the growth is gentle enough to be affordable. Going from 384 steps to 384
thousand is a thousandfold increase in load and, extrapolated, about a tenfold
increase in width. Extrapolating three decades beyond the measured range is not
evidence and is flagged as arithmetic rather than a finding, but the shape is
encouraging where linear would have been fatal.

For comparison, attention holds every position it has seen: its state grows
LINEARLY in stream length and its time quadratically. On this axis the local rule
is not merely competitive but structurally better, which is worth stating
carefully rather than loudly -- it is one axis, on one task, and the 4.0x width
penalty from g1-08 is measured at a single sequence length.

Which raises the obvious follow-up: **the 4.0x price was measured at seq_len=96.
If the two architectures scale differently in stream length, that ratio is a
point on a curve rather than a constant** -- and attention's linear state growth
against this rule's 0.37 exponent says they must diverge. Re-measuring the price
across seq_len is the natural next experiment, and it could move the headline
again in either direction.


PREDICTION 4, CONFIRMED STRUCTURALLY
--------------------------------------
Most of the memory is spent on bindings nobody will ever query: 4 of 95 at the
reference, 4 of 383 at the longest. A mechanism that stored only what would be
asked about would need dramatically less room -- and, as the prediction said,
knowing which those are in advance is the whole problem, and anything that
guessed would be attention smuggled back in.
