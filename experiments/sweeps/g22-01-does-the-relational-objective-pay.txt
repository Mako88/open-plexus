Does the relational objective pay, against a sequential one?
=============================================================

Script: experiments/g22_01_does_the_relational_objective_pay.py
Status: NOT YET DISPATCHED. Predictions registered below before the matrix runs.

ANSWER: pending.


IN PLAIN TERMS
---------------
This project's whole idea is that training a system on how things RELATE to each
other will make it reason, where training it to predict the next word only makes
it continue. That is written down as the thing that, if wrong, means the project
is wrong.

Nobody has ever tested it.

Every experiment here has assumed it. This one takes the same model, the same
data and the same amount of training, and changes only WHAT IT IS ASKED TO
PREDICT -- everything, or only the relationships. Then it checks which one is
better at working out a fact nobody stated.

If predicting everything does just as well, the central idea is in trouble. That
is a real possibility and it is the reason to run it.


WHY THIS EXISTS
----------------
GOALS section 1:

    The bet, stated so it can fail: a system whose training objective is
    *relational* rather than *sequential* will reason rather than continue. If a
    model with a good concept map turns out to reason no better than a next-token
    model of the same size, the central premise is wrong.

That sentence has sat in the goals document unmeasured while every experiment in
the repository was conditioned on it. CLAUDE.md rule 1 describes the shape: a
claim filed under established, sitting upstream of everything, which **no
downstream measurement can reach** because every measurement assumes it.

The rule was written about the literature. This is the same failure pointed at
the project's own premise.


WHY CLOSURE, AND WHY THE CONTRAST IS EXACT
--------------------------------------------
`closure.py` emits `FACT S O R` with the scored target at the OBJECT position, so
**the relational target at a scored position IS the next token at that
position.**

The two arms therefore nest exactly:

    relational   loss taken only where a relation must be produced
    sequential   loss taken at EVERY position, on the next token throughout

The sequential arm's training signal is a strict SUPERSET of the relational
arm's. Same model, same width, same epochs, same optimiser, same data, same
scoring, same seeds. The only difference is which positions the loss is taken at.

A difference cannot then be attributed to the model, the data, the budget or the
readout. That is what makes this a test of the objective rather than of a
configuration -- and configurations are what this project has repeatedly
discovered it was really measuring.


THE ARMS
--------
    majority     always answer the commonest relation        the base rate
    relational   attention, loss at relation positions       the project's bet
    sequential   attention, loss at every position           the opponent
    seq_probe    sequential, then `wo` refitted relationally  A DIAGNOSTIC

`relational` is g14-01's `attention` arm unchanged, which makes it a control on
this harness as well as an arm: it should reproduce 0.282 +/-0.011.

**`seq_probe` is not a competitor and must never be quoted as one.** It gets 8
epochs of output-projection fitting ON TOP of the full sequential budget, so it
has more compute than anything it sits beside. Its only job is to separate *"the
sequential objective did not learn the relations"* from *"it learned them and the
readout does not emit them"*. Decision 118 is why that distinction is worth a
whole arm: this project once published an offline probe on frozen features as a
headline result, and it was evidence about what the features CONTAINED rather
than about what the system reached.


WHAT THIS IS NOT
-----------------
Decisions 095-098 measured all-position training on **our local model**, over
chains, and found it costs composition 1.000 -> 0.40 because the halting GATE is
conflicted -- repaired by giving the gate its own objective (`gate_objective`).

Different model, different task, and a mechanical cause. **This runs on the
attention reference precisely BECAUSE it has no gate**, so that confound cannot
contaminate the objective comparison. Nothing here revives or re-tests 095-098,
and 098's revival condition is untouched.


RESOLUTION, DECIDED BEFORE THE RUN
------------------------------------
g14-01 measured this task's usable band at **0.092** -- attention 0.282 against a
majority floor of 0.190 -- with a standard error of 0.011 at 8 seeds.

That is narrow, and saying so in advance is the point. At 8 seeds the standard
error on a DIFFERENCE between two arms is about 0.016, so a 0.03 effect would be
under two standard errors and unreportable either way.

So this runs at **32 seeds**, putting the difference's standard error near 0.008.

    MIN_DIFFERENCE = 0.030

**Registered before dispatch.** A difference smaller than this is reported as
"below the resolution of this instrument", NOT as a null and NOT as a confirmation
of either side. The instrument's limit is a property of the instrument and gets
stated as one -- 0.030 is a third of the entire usable band, and no amount of
seeds changes that.


PREDICTIONS
-----------
  P1  `relational` reproduces g14-01 on ENTAILED: within 0.02 of 0.282.
      This is the control. If it fails, the harness changed and nothing else
      in this file can be read.

  P2  THE TEST. `relational` beats `sequential` on ENTAILED by more than
      MIN_DIFFERENCE (0.030).

      This is GOALS section 1's bet. Refuted if `sequential` is within 0.030 or
      ahead -- and a refutation here is a finding about the PROJECT, not about
      this experiment.

  P3  On STATED, both arms sit near `majority`. The stated half is a floor by
      construction -- the binding is written one step after the prediction
      point -- so an arm well above it is a leak, which is how the first version
      of g14-01 was caught.

  P4  `seq_probe` lands at or above `sequential` on ENTAILED.
      Refitting the readout cannot destroy information, so a probe BELOW its own
      base model means the fit did not converge and the arm is uninterpretable.

  P5  THE ONE I EXPECT TO BE WRONG. `sequential` lands at or above the majority
      floor of 0.190 on ENTAILED.

      Registered because I am unsure of it and would otherwise be tempted to
      explain either outcome afterwards. If `sequential` lands BELOW the base
      rate -- as our own local rule does, at 0.108 -- then predicting everything
      is not merely a weaker objective on this task, it is an actively harmful
      one, and P2 could be confirmed for a reason that has nothing to do with
      relational structure being good.


WHAT WOULD MAKE EACH OUTCOME MEAN SOMETHING
---------------------------------------------
    sequential >= relational        the extra signal does not hurt and
                                    relational focus buys nothing. **The premise
                                    is weakened at the one place it is stated to
                                    fail.** Not fatal on one task, and it would
                                    make the next question "on which tasks, if
                                    any, does it pay"

    relational -  sequential > 0.03  predicting everything degrades composition.
                                    The premise survives its own first test.
                                    **Read with P5**: if sequential is below the
                                    base rate this says more about the cost of a
                                    dense objective than about relational
                                    structure

    difference < 0.03                below this instrument's resolution. Reported
                                    as that and nothing else. The next move is a
                                    task with a wider band, not more seeds

**A confirmation here is worth much less than a refutation.** One task, designed
by this project, at one scale, on a single-layer reference. GOALS section 1.3 is
explicit that a result at this scale only counts if it transfers.


COST
----
Measured by --cost on this machine, per arm rather than by multiplying the
dearest -- which the first version of the probe did, and reported **72 min per
job against a real ~11**, a 6.5x over-estimate that would have re-scoped the
experiment for no reason.

    majority       0.00 min local     0.01 min at 8x
    relational     0.41 min local     3.29 min at 8x
    sequential     0.40 min local     3.18 min at 8x
    seq_probe      0.55 min local     4.40 min at 8x

    one seed, all four arms:  1.36 min local  ->  ~11 min on a hosted runner
    32 seeds, one per job:    32 jobs at ~11 min

The 8x is CLAUDE.md's measured local-to-runner factor for a 2-worker
`ubuntu-latest` job, not a guess -- the calibration that replaced an assumed 3x
after a matrix came within sight of its own timeout.


MEASURED ON
-----------
openplexus/tasks/closure.py at its calibrated defaults -- 10 people, 24 stated
edges, 6 entailed. Reference at width 128, 16 epochs, Adam at 3e-3, which is
g14-01's converged setting: width 64 sat BELOW the majority floor and 40 epochs
buys 0.007 over 16.
