Can a locally-learned relation representation beat random filling?
===================================================================

Script: tools/generation_delta.py --fill contrastive  (mode to be added)
        tools/relation_contrastive.py  (the representation)
Status: NOT RUN. Predictions registered and COMMITTED BEFORE the run, which is
        the whole point of this file existing before the mode does.

ANSWER: pending.


IN PLAIN TERMS
---------------
When the system walks a chain of relationships -- this person's mother's father's
sister -- it sometimes hits a step whose rule it was never taught. It has to
guess.

Guessing at random already gets 0.6081 on the end task, because kinship is
constrained enough that a wrong guess often still lands somewhere plausible. So
0.6081 is the number to beat, and it is a surprisingly high bar.

A previous attempt at a smarter guess scored **0.5995 -- worse than guessing**.
That is the result this repeats with a different mechanism.

The question: does a relation representation LEARNED from local evidence guess
better than chance, or does it, like the last one, do worse?


WHY THIS EXISTS, AND WHY THE PREVIOUS NUMBER DOES NOT COUNT
-------------------------------------------------------------
On 2026-07-30 a local contrastive rule reached **0.2437 +/-0.0419** on held-out
RULE prediction against 0.0312 untrained
(`docs/options/structured-relations.md`).

**That is the question note 088 calls the wrong one.** Its exact words about the
counted mechanism, which scored 0.223 on the same split:

    a real effect on the wrong question

and the same mechanism then scored **0.5995 end task, below random's 0.6081**.

So the earlier number is the identical shape, one mechanism later, and it settles
nothing. The option record's revival condition names the bar in one line:

    Revival: only if a mechanism beats 0.6081 end-task

This is that test.


WHAT CHANGES BETWEEN THE TWO MEASUREMENTS
-------------------------------------------
    held-out RULE prediction     a linear probe names a composition
    END TASK                     the walk gets the right answer

    random quarter               related rules split across train and test
    ADVERSARIAL, by construction the missing rules are whatever the training
                                 rules do not contain, so a family goes together

The second column is what this runs. The holdout needs no special construction:
`rule_table` is built from the training rules and a gap is any step whose rule is
absent, so the split is structural rather than sampled.


THE ARMS
--------
    gap           refuse to fill. What the table alone completes
    random        fill uniformly at random           <- THE BAR, 0.6081
    wrong-delta   fill with a deliberately wrong one <- the control, 0.5681
    delta         generation delta                   <- the ceiling, 0.9668
    contrastive   nearest relation to compose(left, right) under the learned
                  vectors                            <- NEW

Every arm but the last already exists in `tools/generation_delta.py`. This adds
one `fill` mode and changes nothing else, so an arm moving is the representation
and not the harness.

**`wrong-delta` at 0.5681 is the arm that makes the bar meaningful.** It is BELOW
random, which is what says systematic error costs more than noise here -- so
scoring under 0.6081 is not a small miss, it is evidence of a representation that
is confidently wrong.


PREDICTIONS
-----------
  P1  THE TEST. `contrastive` beats `random`'s 0.6081 on the end task.

      Refuted if it lands at or below. **A refutation here is the same finding as
      note 088's**, and the honest reading would be that an objective and
      negatives do not rescue a representation that counting could not build --
      which would make the whole extensional direction, not just one mechanism,
      the thing that is wrong.

  P2  `contrastive` beats `wrong-delta`'s 0.5681.

      A weaker bar and a diagnostic. Below it, the learned representation is
      worse than deliberately choosing a wrong relation, which would mean the
      contrastive objective learned structure that is actively anti-correlated
      with composition rather than merely uninformative.

  P3  `contrastive` does NOT reach `delta`'s 0.9668.

      Registered because I expect it and want that on the record rather than
      available afterwards. Generation delta solves an exact linear system over
      loop constraints and recovers 20/20 deltas exactly; a learned approximation
      matching it would be surprising enough to suspect a leak first.

  P4  THE ONE I AM LEAST SURE OF. The gap between `contrastive` and `random` is
      SMALLER than the gap between 0.2437 and 0.0312 suggested.

      Held-out rule prediction improved roughly eightfold over untrained. If that
      transferred proportionally, the end task would clear 0.9. It will not, and
      the reason is worth stating in advance: end-task accuracy is dominated by
      the steps whose rules the table already HAS, so a better guess only moves
      the subset where it is consulted.

      **If this prediction is wrong in the other direction** -- the end task
      moving as much as rule prediction did -- that is a signal the two are
      measuring the same thing, and the "wrong question" framing above is itself
      wrong.


WHAT WOULD MAKE THIS NOT COUNT
--------------------------------
**A leak.** The vectors must be trained only on rules present in `rule_table`. If
a rule the fold is asked to supply also trained the representation, the number is
the 0.4188 artefact measured on 2026-07-30, not a result.
`the-held-out-rule-trains-the-representation` in `tools/mutate.py` is that control
and is caught; this run must additionally assert the two rule sets agree.

**A tuned representation.** Width, epochs, learning rate and temperature were
chosen on the RULE-prediction task. They are carried here unchanged and that is
recorded as a carried constant per CLAUDE.md rule 2 -- `width 32, epochs 8,
lr 0.05, temperature 0.1, chosen on held-out RULE prediction, not on this task`.
Tuning them here and comparing against untuned baselines is the one-sided sweep
the price-of-locality calibration is about.


COST
----
To be measured with a probe before dispatch rather than estimated. The
representation trains in seconds at width 32 over 62 rules; the fold is symbolic
and cheap. This is expected to be a LOCAL run rather than a matrix, and if that
turns out to be wrong the costing says so before anything is dispatched.


MEASURED ON
-----------
CLUTRR-symbolic `gen_train23_test2to10`, layout `kinship`. Relation vectors at

the training rules only.
