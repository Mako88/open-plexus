The gate on the credit-assignment scheme -- is the substrate predictable at all?
================================================================================

Script: experiments/g1_01_predictability.py
Status: RUN. Predictions 1-4 held, 5 partly refuted. THE GATE IS SHUT -- and
        the reason it is shut turns out to be a defect in our own task design,
        not a fact about substrates.


IN PLAIN TERMS
--------------
Our whole plan for how learning works rests on one idea: each part of the network
guesses what it is about to receive next, then compares its guess with what
actually arrives, and the difference is what it learns from.

That only works if there is something to guess. If what arrives next is pure
surprise, the guess carries no information and there is nothing to learn from.

This measures whether the guess is possible at all -- BEFORE building anything
that guesses. It is one small experiment and it decides whether the plan is
alive.

There is a trap. Some of what arrives is easy to predict for boring reasons: our
distracting filler runs on a fixed cycle, so predicting it is like predicting
that Tuesday follows Monday. That would produce an impressive-looking number that
means nothing. So the results are split: the boring part and the part that
actually matters, separately.


QUESTION
--------
Can a linear readout on a frozen substrate's state predict the token arriving
k steps later, above the majority-class rate, at positions carrying task content
rather than filler?

docs/notes/005 promoted this to the single most important unmeasured item in the
project, because the published evidence that appeared to support a predictive
objective turned out to describe a supervised, target-clamped variant we cannot
use. The scheme now rests on its own structural argument plus this gate.


THREE DEFECTS INHERITED AS WARNINGS
------------------------------------
PLEXUSBRIEF.md §6 records three defects in the predecessor's version of this
probe. All three are guarded here from the start, which is the whole value of
having inherited a record of what did not work:

1. Its state was the raw sparse spike vector and the probe sat at the floor even
   at horizon 0 -- it could not decode what was happening at that very moment.
   -> horizon 0 is reported in every row as the connection control.

2. No horizon-0 control and no majority-class floor, so "the future is
   unpredictable" and "this probe decodes nothing" produced the same table.
   -> both reported, always.

3. It conflated a schedule-driven cue identical in every episode with the cue
   groups carrying random content, scoring 0.797 while predicting no content
   whatever.
   -> split by the kind of position being PREDICTED: filler versus task.


PREDICTIONS -- written before the run
--------------------------------------
1. Horizon 0 is ~1.000 in every condition. Already known indirectly: g0-02's
   connection control decoded the current token at 1.000. If it is not, the
   probe is broken and nothing else in the table counts. (Recorded this time as
   a prediction derived from evidence already in hand -- g0-03 was refuted by
   failing to do exactly that.)

2. filler / structured, horizon 1: HIGH, 0.8+. The filler is a deterministic
   cycle over spare keys, so the next filler token is a function of position,
   and the substrate's state encodes position well enough to recover it. This
   number is expected to be impressive and to mean nothing.

3. filler / random, horizon 1: at base rate. Random filler is unpredictable by
   construction. The gap between this row and (2) is the measurement of how much
   of any headline number is the cycle.

4. task / either filler, horizon 1: AT OR NEAR BASE RATE. This is the real
   prediction and it is a pessimistic one. Task positions are keys and values
   drawn at random; nothing in a frozen substrate's state should anticipate
   which random key arrives next.

5. Predictability decays with horizon everywhere except structured filler, which
   should stay high at all horizons because a cycle is equally predictable at any
   distance.

The prediction that decides the project's direction is (4), and the honest
position is that we expect it to be NEGATIVE. That is uncomfortable to write
before a run, which is precisely why it is being written before the run.


WHAT WOULD REFUTE WHAT
-----------------------
- horizon 0 not ~1.000        -> probe broken; discard the table
- task rows above base        -> THE GATE OPENS. A frozen substrate anticipates
                                 its own task-relevant input, and a predictive
                                 objective has real signal to learn from
- task rows at base           -> the gate is SHUT for this task and this
                                 substrate. See below -- this does not
                                 necessarily kill the scheme, and the difference
                                 matters
- filler/structured at base   -> the substrate does not even encode position;
                                 something is wrong with the substrate, not the
                                 hypothesis


IF THE GATE IS SHUT, WHAT DOES IT ACTUALLY MEAN
------------------------------------------------
Written before the result so that a negative cannot be quietly reinterpreted
afterwards into something more comfortable.

A negative here means: THIS substrate, on THIS task, carries no linearly
decodable information about its own next task-relevant input. It would NOT
immediately mean the predictive scheme is dead, for three specific reasons, and
each is a claim that would then need testing rather than asserting:

  a. MQAR's task content is random by construction. Keys and values are drawn
     uniformly, so there may be nothing to predict IN PRINCIPLE at those
     positions -- an ideal predictor would also fail. That would make MQAR the
     wrong task on which to ask this question, not evidence against prediction.
  b. Linear decodability is a lower bound on what is present.
  c. A frozen substrate is not a trained one.

But (a) is the important one and it cuts deep: if the benchmark chosen for G0
has no predictable structure at task positions, then the task and the
credit-assignment scheme are MISMATCHED, and docs/notes/001's property P2 --
that the objective and the metric should be the same quantity -- is not actually
satisfied the way that note claimed. That would be a real finding about our own
plan rather than about the world.

THE HEADLINE THAT WOULD HAVE BEEN WRONG
----------------------------------------
Look at the 'all' column, structured filler, horizon 1: 0.666 against a base
rate of 0.030. Twenty-two times chance.

Written up on its own that is a spectacular result: "a frozen substrate predicts
its own next input at twenty-two times the base rate, before any learning at
all." It is also entirely meaningless. The 'task' column at the same horizon is
0.058 against a base of 0.051.

ALL of it is the filler cycle. None of it is content.

This is PLEXUSBRIEF §6 defect 3 reproduced exactly -- the predecessor scored
0.797 by conflating a schedule-driven cue with the content-carrying groups. We
did not avoid it by being careful. We avoided it because the predecessor wrote
down what went wrong and the split was built into the probe before it first ran.
That is the entire value of inheriting a record of failures.


PREDICTIONS
-----------
1. HELD. Horizon 0 is 0.995-1.000 everywhere. The probe works, so the rest of
   the table counts. (Derived in advance from g0-02's control rather than
   guessed -- the correction g0-03 earned.)

2. HELD, and closely. Predicted 0.8+ for filler/structured at horizon 1;
   measured 0.810.

3. HELD. filler/random at horizon 1 is 0.029 against a base of 0.037 -- at
   chance, as an unpredictable-by-construction stream must be.

4. HELD, and this is the gate. Task positions sit at base rate in every
   condition and at every horizon: 0.058/0.051, 0.062/0.042, 0.074/0.045 under
   structured filler, and the same under random. The substrate carries no
   linearly decodable information about its own next task-relevant input.

5. PARTLY REFUTED. Predicted structured filler stays high at all horizons
   because a cycle is equally predictable at any distance. It decays: 0.810 ->
   0.692 -> 0.416. The cycle's phase is disrupted by queries, which land at
   random offsets, so the further ahead you look the more likely an
   unpredictable interruption has intervened. A cycle is only equally
   predictable at all distances if nothing perturbs it.


WHAT IT MEANS -- AND THE PRE-WRITTEN ESCAPE HATCH IS THE RIGHT ONE
-------------------------------------------------------------------
The section above, written before the run, listed reason (a) as the important
one if the gate came back shut: MQAR's task content is random by construction,
so there may be nothing to predict IN PRINCIPLE at those positions, and an ideal
predictor would fail too.

That is exactly what happened, and it is sharper than anticipated.

Keys are drawn uniformly at random. Which key arrives next is genuinely
unpredictable from any amount of context. A perfect predictor scores at base
rate there. So this result is NOT a measurement of the substrate's poverty --
it is a measurement of the task having no predictable content at those
positions.

THE REAL FINDING, which the note flagged as possible and which now needs acting
on:

  docs/notes/001 P2 claims the task's native metric IS next-symbol prediction,
  so that the objective and the score are one quantity. IN THIS GENERATOR THAT
  IS FALSE, and the probe is what exposed it.

  At a query position the target is the paired VALUE -- but that value is never
  emitted into the token stream. The next token after a query is filler. So
  "predict your next input" and "answer the query" are different questions here,
  and P2 is not satisfied.

  In the autoregressive framing the literature uses, the query is FOLLOWED BY
  ITS ANSWER in the sequence, so predicting the next token at a query position
  IS the task. Our generator uses a classification framing -- targets as labels
  beside the stream rather than tokens within it. Both are legitimate; only the
  first satisfies P2.

So the gate is not shut. It has not been properly asked yet, because it was
asked of a generator that does not emit the thing worth predicting.

NEXT: add an autoregressive mode that emits the value token after each query,
and re-run this probe. Then the task column at horizon 1 measures exactly the
thing the credit-assignment scheme is supposed to learn, and a null there would
be a real null.

This is a defect in our task design found by a probe aimed at something else,
which is the second time a control has been worth more than the measurement it
was guarding.

THE GATE IS SHUT, AND IT WAS NEVER GOING TO BE OTHERWISE
---------------------------------------------------------
Answer positions at horizon 1: 0.135 against a base of 0.140 under structured
filler, 0.140 against 0.140 under random. At base rate. The control at horizon 0
is 1.000, so the probe works.

But look at what the question became once P2 was satisfied. At a query position
the state holds the key; predicting the next token means producing the value.
THAT IS THE RECALL TASK. g0-02 already measured a frozen substrate at 0.180 on
exactly that, and this is the same measurement wearing different clothes.

So this run is CONSISTENT with everything already known and adds no information
about the substrate. Fixing P2 made the probe correct and simultaneously made it
circular: at answer positions, "is there signal to learn from" and "have you
already solved the task" are the same question.

That is worth stating plainly because it was not obvious in advance, and because
it means the gate as originally posed cannot be answered this way.


THE FINDING THAT IS NEW, AND IT CORRECTS docs/notes/002 §7
-----------------------------------------------------------
Read the filler column against the answer column.

  filler, structured, horizon 1:   0.824   (base 0.042)
  answer, structured, horizon 1:   0.135   (base 0.140)

There IS abundant predictable structure in this task. It is all in the filler,
and it is worth nothing.

docs/notes/002 §7 recorded a tension: note 001 wants irrelevant material because
a random substrate cannot discard selectively; note 002 objects that random
material is unpredictable and starves a predictive objective. Its proposed
resolution was STRUCTURED FILLER -- irrelevant but predictable, so the objective
has signal.

MEASURED, THAT RESOLUTION DOES NOT WORK. It does not fix starvation; it replaces
starvation with distraction:

  - random filler     -> 0.029. No signal at all. The objective starves.
  - structured filler -> 0.824. Abundant signal, ALL of it task-irrelevant.

A predictive objective trained here would spend almost all of its gradient
learning to continue a counting cycle. The proposed fix separated
"hard-to-retain" from "impossible-to-predict" exactly as intended, and produced a
third problem nobody named: EASY-AND-USELESS.

Both filler modes are bad for a predictive objective, for opposite reasons, and
the note treated one of them as the solution.


WHAT THIS IMPLIES, STATED AS A PROBLEM RATHER THAN A FIX
---------------------------------------------------------
A predictive objective needs a task whose TASK-RELEVANT content is predictable
in principle from context, but not already solved by the untrained substrate.
MQAR does not obviously provide that:

  - its keys and values are drawn at random, so the only predictable
    task-relevant token is the answer;
  - and the answer is predictable only by an agent that has already done the
    retrieval.

There is no gradual slope here. It is a step: you cannot predict the answer at
all until you can retrieve, at which point you can predict it perfectly. A
predictive objective learns from a slope.

That is a real problem for the task/objective pairing and it is NOT resolved by
this note. Three directions, none of them measured, and none to be adopted
before being argued properly:

  a. A task with graded predictable structure -- language-like statistics, where
     partial context yields partial predictability, rather than random symbols.
  b. Keep MQAR for G0 as a capability benchmark and use a DIFFERENT task to
     drive the predictive objective. This breaks P2 on purpose and honestly,
     rather than believing it while it is false.
  c. Accept that the predictive objective needs a bootstrapping signal that MQAR
     cannot supply, and reconsider docs/notes/002's mechanism ranking.

docs/notes/002 §8 already lists "it does not establish that any of this learns"
as an open item. This narrows it: the scheme may be sound and simply have been
paired with a task that cannot train it.
