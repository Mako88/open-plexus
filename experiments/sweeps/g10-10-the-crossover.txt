At a fixed memory budget, does the store ever beat a cache?
===========================================================

Script: experiments/g10_10_the_crossover.py
Status: RUN. Three budgets, nine item counts, seconds, local.

ANSWER: **NO CROSSOVER ANYWHERE TESTED.** At equal memory a table is at least as
        good at every item count, at every budget. The store is perfect while
        items stay under about the store's width and collapses after; the table
        is exact until it runs out of entries, and at equal budget it has 32
        times as many.

        **But see WHAT THE DATA IS**: these are random pairs, and superposition
        is a compression scheme. Incompressible data is where it cannot pay.


IN PLAIN TERMS
---------------
Give both structures the same amount of memory and keep adding things to
remember.

The blended store is perfect until it holds about as many things as it has
dimensions, then falls apart quickly. The lookup table is exact until it
physically runs out of room -- and for the same memory it has room for far more.

There is no point at which the blend wins. The argument that it would win "once
there are enough items" does not survive being measured.


THE RESULT
-----------
    budget 1024 -- a 32x32 store, or 512 cache entries
        items       8    16    32    64   128   256   512  1024  2048
        store   1.000 0.875 0.625 0.258 0.090 0.040 0.020 0.010 0.000
        cache   1.000 1.000 1.000 1.000 1.000 1.000 1.000 0.500 0.250

    budget 4096 -- a 64x64 store, or 2048 cache entries
        store   1.000 1.000 1.000 0.988 0.830 0.460 0.160 0.063 0.003
        cache   1.000 1.000 1.000 1.000 1.000 1.000 1.000 1.000 1.000

    budget 16384 -- a 128x128 store, or 8192 cache entries
        store   1.000 1.000 1.000 1.000 1.000 0.993 0.930 0.527 0.227
        cache   1.000 1.000 1.000 1.000 1.000 1.000 1.000 1.000 1.000

**The store's useful capacity tracks its width**, which is note 020's `sqrt(d/N)`
law showing up as a hard wall: about 64 items at width 64, about 256 at width
128. **A cache entry costs two integers**, so the same budget buys 2,048 or 8,192
of them.

The store's memory is fixed and the cache's grows -- that part of the argument
is true. It does not help, because the cache starts 32x ahead per unit memory
and the store's fixed cost buys a capacity that is fixed too.


PREDICTIONS -- A DECISION RULE, WRITTEN BEFORE THE RUN
-------------------------------------------------------
    a crossover exists          -> superposition earns its place above some item
                                   count, and that count is the project's
                                   central justification
    the cache wins at every n   -> at a fixed budget a table is simply better
                                   here, and the answer to "can traditional
                                   computing replace it" is yes for this
                                   workload
    both collapse together      -> the budget is the constraint, not the
                                   structure

**The second fired.** I expected the first, on the strength of the "fixed cost"
argument that note 030 and I had both repeated without checking the arithmetic.


WHAT THE DATA IS, AND WHY IT MAY BE THE WHOLE ANSWER
------------------------------------------------------
**These are random cue-value pairs with no structure.**

Superposition is a lossy compression scheme. `n` independent random pairs contain
`n` items of irreducible information, so nothing can store them in less than `n`
somethings -- and a table's "something" is two integers while the store's is a
share of a matrix it must pay for whether or not the data compresses.

**So this measures superposition on exactly the data where it cannot pay.** And
that is not an accident of this run: MQAR and `reward_recall` both use random
symbols *by design*, to isolate mechanisms from content. **The project's task
suite is deliberately incompressible**, which is a reasonable choice for
measuring gates and possibly the worst possible choice for measuring whether
superposition is worth having.

That is a hypothesis with a clean test -- the same comparison on data with real
structure -- and it is NOT a claim this run supports. Stated here because the
reading "superposition is useless" would be the natural one and is not warranted
by random pairs alone.


WHAT THIS CANNOT SAY
----------------------
Nothing about learning, generalisation, or emergence. This is exact recall of
arbitrary pairs, which is the one thing both structures do directly and the only
comparison available without a readout in the way. **A cache has no story at all
for goal 1**, and this does not give it one.


WHAT WOULD REFUTE WHAT
-----------------------
- a crossover at large n         -> NOT OBSERVED to 2,048 items
- the store degrades gracefully
  enough to stay useful          -> NOT OBSERVED: 0.003 at 2,048 items on a
                                    4,096 budget, against a perfect table
- the cache runs out first       -> only at budget 1024, where it still leads


COST
-----
Seconds, local, one seed per cell. **One seed** -- the shape is monotone and far
outside seed noise, but individual cells are soft.
