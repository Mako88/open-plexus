Can a system that ASKS separate a confound a system that WATCHES cannot?
=======================================================================

Script: experiments/g44_01_can_asking_beat_watching.py
Status: PREDICTIONS REGISTERED BEFORE THE INSTRUMENT EXISTS. Nothing has been run.

`docs/options/intervention.md` names this as the falsifier and says it can be
built before any learning rule changes: *"does a system permitted `n`
interventions separate a confound that an observer of the same stream cannot? If
it cannot, the whole direction is refuted cheaply."*


IN PLAIN TERMS
--------------
Everything this project has built so far WATCHES. A stream of moments goes past,
things turn up together, and what keeps turning up together becomes one thing.

That works until something is reliably present for a reason of its own. If a lamp
is switched on every time the dog is in the room, the lamp and the dog co-occur
exactly as strongly as the dog's bark does. We measured this and it is not a flaw
in our counting: **a stream of observations contains nothing that separates
"always there when" from "part of".** Any counting method reads the same numbers.

The proposed escape is to stop only watching. Ask for the dog **without** the
lamp. If the world can produce that, the lamp was never part of the dog. If it
cannot — if every attempt to get the dog comes with the bark attached — then the
bark is not a coincidence.

**A constitutive part is one you cannot get an occasion without.** That is the
whole idea, and it is a claim about causation that no amount of counting reaches.

This run asks whether that actually works, and it is written to be able to say no.


WHAT IS BEING MEASURED
----------------------
    separation   the score gap between the weakest TRUE partner of a concept
                 and the confound. `g39-06`'s quantity, unchanged, so the two
                 runs are directly comparable
    refusals     how often the world could NOT supply the requested occasion.
                 **The signal itself**, not an error: a request that cannot be
                 met is what "you cannot have this without that" looks like
    budget       interventions permitted, as a fraction of stream length

THE ARMS

    watch        `g39-06`'s observer, on the same stream. THE BASELINE, and the
                 thing that must be beaten for the direction to survive
    ask-random   spends the same budget on RANDOM `(present, absent)` pairs.
                 **The control that decides whether asking helps or whether
                 CHOOSING WHAT TO ASK helps** -- without it, "intervention
                 works" would be indistinguishable from "a differently-sampled
                 stream works"
    ask-targeted names its current best-scoring surface as `present` and its
                 next-best as `absent` -- the cheapest policy that uses what
                 has been learned so far, and it asks whether the runner-up
                 can be detached from the leader

WHAT AN INTERVENTION IS, exactly

    `world.ask(present, absent)` -- ONE occasion containing surface `present` and
    not containing surface `absent`, or a REFUSAL. One draw, not a search: the
    world attempts it once and a refusal means *"I tried and it came with that
    attached."*

    It costs one occasion from the same budget the observer spends on watching,
    so **no arm sees more data than another.** An arm that both watched a full
    stream and intervened would be measuring sample size.

**CORRECTED BEFORE ANYTHING WAS BUILT.** The first version of this section had
`world.without(subject, surface)` -- naming the CONCEPT. That is not an
intervention a learner can make: `Occasion.subject` is marked *diagnostics only*
in `occasions.py` precisely because handing it over is handing over the answer,
and a system that can name the concept it wants has already solved the problem
this run is about.

Asking by SURFACE needs nothing the learner has not seen. It is strictly weaker
and it is the honest form.

**And ONE DRAW rather than retry-until-satisfied is the load-bearing choice.** A
rejection loop with a retry cap would make the refusal rate a function of the
cap, which is a knob that could manufacture P3. One draw makes the refusal rate
exactly the conditional presence of `absent` given `present` -- which is the
causal quantity the whole idea rests on, measured rather than tuned.


THE DEGENERATE CASES, named before the run rather than discovered
    - **A constitutive surface must be refusable and a confound must not be**,
      or the instrument cannot express the question. `presence < 1.0` means a
      true partner is ALREADY absent sometimes, so "without" is satisfiable for
      both and the mechanism has to work on RATES rather than on possibility.
      **This is the hard case and it is the one built**; an all-or-nothing world
      would make the test trivial and prove nothing (rule 10).
    - **A refusal is only informative if refusals are possible at all.** If the
      world can always comply, `refusals` is 0 everywhere and the arms differ
      only in sampling. The run reports the refusal rate per arm so that reading
      is available rather than assumed.
    - **The floor is `watch`, not zero.** `g39-06` puts the confound's margin at
      0.0096 -- small, but positive and not chance. Any claim for intervention
      is a claim against 0.0096, not against nothing.


PREDICTIONS
-----------
P1  **ASKING BEATS WATCHING ON THE CORRELATED CONFOUND.** `ask-targeted`'s
    separation exceeds `watch`'s by more than 0.05 at a budget of 0.10, on the
    confound `g39-06` measured at 0.0096.
    REFUTED IF it does not. **Then the direction is refuted cheaply and that is
    the point of running it first** -- no learning rule has been touched, and
    `intervention.md` becomes a record of a measured dead end rather than an
    open option.

P2  **AND IT IS THE TARGETING, NOT THE ASKING.** `ask-targeted` beats
    `ask-random` by more than 0.02 at the same budget.
    REFUTED IF `ask-random` does as well. Then what helps is that the stream was
    resampled, not that the system chose -- which is a much weaker claim and
    would mean the instrument, not the policy, is doing the work.

P3  **THE REFUSAL RATE IS WHAT CARRIES THE SIGNAL.** `ask-targeted`'s advantage
    over `watch` correlates with its refusal rate across budgets: at a budget
    where refusals are near zero the advantage is near zero.
    REFUTED IF the advantage appears without refusals. Then whatever is helping
    is not *"a constitutive part cannot be withheld"*, and the account in this
    file is wrong even if the numbers are good.

P4  **A MERELY-COMMON DISTRACTOR NEEDS NO INTERVENTION.** On `g39-06`'s
    non-correlated distractor, refused by 0.4490 by watching alone, `ask-targeted`
    and `watch` agree within 0.02.
    REFUTED IF intervention helps there too. Then it is improving something
    general about the estimate rather than doing the specific job claimed, and
    P1's reading would be wrong.

P1 is written expecting the mechanism to work, which is the outcome that costs
more work. **P3 is the one that decides whether the explanation is right**, and
it can fail while P1 and P2 both hold.


MEASURED ON
-----------
Local, one process. Same world as `g39-06` so the baseline transfers.

    task     occasions.py, MNIST + FSDD + 10 words shape, one correlated
             distractor at 63% specificity and one merely-common distractor
    budgets  0.00 (= watch), 0.02, 0.05, 0.10, 0.20 of stream length
    seeds    8. `g36-01`'s calibration: three seeds miss a one-in-eight failure
             about 67% of the time, and this run has a perfect-score risk in the
             refusal column

**The instrument does not exist and building it is most of this run.**
`occasions.py` GENERATES a stream and has no notion of a request. What is needed
is a `World` that can be ASKED, with the generator unchanged underneath it, so
every earlier result stays reproducible.


THE C1 QUESTION, ASKED HERE BECAUSE `intervention.md` SAYS TO ASK IT EARLY
--------------------------------------------------------------------------
**An intervention is a request that the world show something.** On a network of
consumer devices there may be nothing to ask and nobody obliged to answer, and a
mechanism that requires a cooperative world is not obviously compatible with
`GOALS.md` §1's constraints.

**This run does not answer that and does not pretend to.** It answers whether
intervention buys anything at all, which is worth knowing before the harder
question is spent on. If P1 is refuted, C1 never has to be argued.

Stated so it is a known gap rather than a discovered one.
