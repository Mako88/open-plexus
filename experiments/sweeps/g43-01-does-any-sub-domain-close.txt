Does any SUBSET of a real graph's relations close, when the whole does not?
==========================================================================

Script: experiments/g43_01_does_any_sub_domain_close.py
Status: PREDICTIONS REGISTERED BEFORE THE SCRIPT EXISTS. Nothing has been run.

`g23-03` named this computation and left it unbuilt: *"the replacement question —
does some SUBSET of a graph's relations close consistently — is a
largest-consistent-subset search rather than a null space over all relations, and
it is unbuilt."* This builds it.


IN PLAIN TERMS
--------------
Our best result on family-tree puzzles leans on an arithmetic trick. Every family
relationship moves you a certain number of generations — father is one up, son is
one down — and around any closed loop those have to cancel out. Knowing that lets
the system fill in a step it was never taught.

The trick needs the domain to HAVE such a quantity. Family trees do. We checked a
large real-world knowledge graph and it does not, and not even approximately.

But "the whole graph has no such quantity" is not the same as "no part of it
does." A knowledge graph covers films and sports and geography all at once, and
there is no reason those should share one accounting system. Maybe the
geography relations balance among themselves even though the whole thing does not.

If some corner of a real graph closes, the trick is a tool you can point at parts
of a problem. If none does, it is a property of family trees and we should stop
treating it as a general mechanism.

**The trap, and it is the whole difficulty.** You can always make a set of
relations "balance" by making the set small enough. With fewer facts than
unknowns the arithmetic has spare room and a solution exists for free, meaning
nothing. So the finding is only real if the closing subset has far more evidence
than it has unknowns — and if it beats the same measurement on deliberately
scrambled data.


WHAT IS BEING MEASURED
----------------------
    dim          the null-space dimension of the cycle-constraint matrix
                 restricted to loops lying ENTIRELY inside a subset
    loops/|S|    evidence per unknown. **The number that says whether a dim >= 1
                 means anything**
    shuffled     the same, with relation labels permuted within loops

THE ARMS

    by-domain    FB15k-237's relation names are paths -- `/people/person/...`,
                 `/film/film/...`. Grouping by the leading segment is a
                 partition the DATA supplies rather than one we invent, which
                 is what keeps this from being a search over 2^237 subsets
    greedy       drop the relation whose removal most lowers the smallest
                 singular value, repeat until dim >= 1. Reports the size at
                 which it happens and the loops/|S| there
    shuffled     THE CONTROL, run on both arms

THE DEGENERATE CASE, computed in advance rather than discovered
    `dim >= |S| - rank` and `rank <= min(loops, |S|)`, so **any subset with
    fewer loops than relations has dim >= 1 by arithmetic alone**. That is the
    null recovery for this metric and it is not zero. Every reported dim carries
    its loops/|S| beside it and any cell below a ratio of 1 is uninformative by
    construction.

    `CLAUDE.md`'s g32-01 calibration is exactly this failure — a control
    predicted near zero came in at 0.3189 to 0.5078 because the metric's
    do-nothing value was 0.5. Here the do-nothing value is computable from two
    inequalities and there is no excuse for not having it first.


PREDICTIONS
-----------
P1  **NO SUB-DOMAIN CLOSES NON-TRIVIALLY.** No `by-domain` subset with
    loops/|S| >= 10 has dim >= 1.
    REFUTED IF one does. Then the mechanism is pointable at parts of a real
    graph, `note 104`'s scoping is too pessimistic, and the next question is
    what that sub-domain's conserved quantity MEANS.

P2  **THE SMALL SUBSETS THAT DO CLOSE ARE THE DEGENERATE ONES.** Every
    `by-domain` subset with dim >= 1 has loops/|S| < 10, and the correlation
    between dim >= 1 and a low ratio is visible without a statistic.
    REFUTED IF a well-evidenced subset closes while a poorly-evidenced one does
    not. Then dim is tracking something other than how constrained the system is.

P3  **GREEDY BUYS NOTHING.** The subset size at which greedy first reaches
    dim >= 1 has loops/|S| < 10 as well, so it reaches closure by running out of
    evidence rather than by finding structure.
    REFUTED IF greedy finds a large well-evidenced closing subset. That would be
    the strongest possible outcome and would make the mechanism general.

P4  **AND THE CONTROL WILL NOT SEPARATE.** The shuffled graph reaches dim >= 1
    at the same subset sizes and the same loops/|S| as the real one, within one
    step.
    REFUTED IF the real graph closes at systematically larger subsets than the
    shuffled one. **Then there is real structure even where dim over the whole
    graph is 0**, and P1's verdict is about our search rather than about the
    graph.

P1 through P3 are written expecting the null, which is the outcome that keeps
`note 104`'s scoping and says the invariant is a property of kinship. P4 is the
one that could overturn all three, and it is the reason the control is run on
both arms rather than once.


MEASURED ON
-----------
Local, one process. No model, no training, no walk -- linear algebra over cycle
constraints, the same computation `tools/invariant_dimension.py` performs over a
whole graph.

    data     data/fb15k237/train.txt, 272,115 edges, 237 relations
    control  CLUTRR kinship, which has dim 1 and must keep it under by-domain
             restriction to a single group -- it has only one
    seeds    the shuffle is seeded; the graph is a fixed file and does not move

**The CLUTRR control is not decoration.** A subset search that cannot find
kinship's own invariant when handed kinship is broken, and that failure would
look exactly like a null on FB15k-237.


COST
----
`tools/invariant_dimension.py` over the whole of FB15k-237 -- 267,089 loops by
234 relations, one SVD -- runs in well under a minute. A subset is strictly
smaller. The by-domain arm is one SVD per group and there are on the order of
tens of groups; greedy is one SVD per removal step and is the expensive arm.

Estimated **5 to 20 minutes** local. Local rather than Actions: minutes, not a
matrix.

Recorded after the run: **51.1s**, well under the estimate. The first design cost
more than the run did — see below.

SCORECARD
---------
  P1  **HELD, and more completely than written.** Predicted no `by-domain`
            subset with loops/|S| >= 10 would close. **None closes at any
            ratio**, including `award` at 947.6 and `people` at 814.1.

  P2  **VACUOUS.** It predicted that the subsets which DO close are the
            poorly-evidenced ones. Nothing closes, so there is no population to
            range over. Recorded as vacuous rather than held: a prediction with
            an empty subject is not evidence about anything.

  P3  **VACUOUS for the same reason.** The ladder never reaches dim >= 1, so
            there is no size at which closure "first happens" and nothing to say
            about the evidence ratio there.

  P4  **VACUOUS, and this is the one that hurts.** The control was supposed to
            be the falsifier — real closing at larger subsets than shuffled would
            have meant structure. Neither closes anywhere, so the comparison has
            no content.

            **In the FIRST version of this script it had content, and it pointed
            the wrong way.** See below.


THE NEAR-MISS, AND IT IS THE FINDING
------------------------------------
**The first version of this script reported a result.** Whole graph dim **3**.
Four domains closing: `film` 2, `location` 1, `education` 4, `government` 1, every
one of them flagged `closes, INFORMATIVE` at ratios in the hundreds.

All of it was an artefact. `restricted()` called `inv.dimension`, **took only the
rank, and recomputed the dimension itself** as `len(columns) - rank` — which puts
back the all-zero columns `dimension` deliberately excludes. A relation appearing
in no within-subset loop has an all-zero column and joins the null space for free.

The tell, once looked for, is exact: **each spurious dim equals that domain's
no-loop count.** film 2 and 2, location 1 and 1, education 4 and 4, government 1
and 1.

**`dimension`'s own docstring names this failure and the graph it first appeared
on** — DBpedia read as *"two conserved quantities"* and both were relations that
never close a loop. It was reproduced here by discarding that function's answer
and recomputing it worse.

**AND THE CONTROL MADE IT MORE CONVINCING, NOT LESS.** This is the part worth
carrying away. Shuffling spreads each loop's coefficients across all 237 columns,
so no column is all-zero and the artefact **cannot occur in the shuffled arm**.
The first table therefore read:

    real       four domains close
    shuffled   nothing closes

which is precisely the signature of a genuine effect that a control has confirmed.
A shuffle control tests whether a result survives destroying the *meaning* of the
data; it does not test whether the result survives a bug in the measurement, and
here it actively concealed one by removing the bug's precondition.

**What caught it was neither the control nor the tests.** It was that the
whole-graph row said dim 3 where `tools/invariant_dimension.py --graph` had said
dim 0 on the same file an hour earlier. Two answers to one question, from two
pieces of code that should agree.


WHAT THIS SETTLES, AND WHAT IT DOES NOT
---------------------------------------
**Settled: the additive invariant is a property of kinship, not a general
mechanism.** FB15k-237 has none over all 237 relations, none over any of its 30
name-derived sub-domains, and none over its best-evidenced 2, 4, 8, 16, 32, 64 or
128 relations. `note 104` found the same for two DBpedia extracts. The mechanism
worth the difference between 0.6061 and 0.9076 on CLUTRR's deepest bucket gets
nothing on any of them.

**Not settled: whether SOME partition closes.** The partition here is by relation
NAME, which the data supplies and which is therefore honest, but it is one
partition out of very many. A subset search that is not name-derived remains
unbuilt, and this run says nothing about it — only that the obvious grouping, the
best-evidenced prefixes, and the whole all fail.

**Not settled: whether additivity is the right invariant.** Every measurement
here asks whether displacements SUM to zero around a loop. A domain could have a
conserved quantity that is multiplicative, or modular, or vector-valued, and this
computation would report dim 0 for all of them. `note 090` already says *"deltas
add"* is a design choice; this establishes that the choice does not transfer, not
that no choice would.
